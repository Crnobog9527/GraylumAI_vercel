**为什么要做:** 实时捕获生产环境错误，避免用户投诉才知道问题

**复制给 Claude Code:**
```

1. 安装依赖:
   npm install @sentry/nextjs

   - sentry.client.config.ts (前端错误捕获)
   - sentry.server.config.ts (后端错误捕获)

   - DSN: 使用环境变量 NEXT_PUBLIC_SENTRY_DSN
   - 环境标识: development / production

   - 忽略错误: 网络超时、用户取消请求

## 🔐 阶段 2: 安全加固 (必做 | 1-2天)

### ✅ 步骤 2.1: Row Level Security 全面检查

**为什么要做:** 确保用户无法访问其他用户的数据

**复制给 Claude Code:**
```
任务: 审计和修复 Row Level Security 策略

要求:
1. 生成完整的 RLS 审计报告:
   
   检查所有表:
   - users
   - conversations
   - messages
   - subscriptions
   - credits_transactions
   - [其他所有表]

   对每个表报告:
   a. RLS 是否启用
   b. 现有策略列表
   c. 策略是否覆盖所有操作(SELECT, INSERT, UPDATE, DELETE)
   d. 策略逻辑是否正确(检查 auth.uid() 使用)
   e. 管理员策略是否存在

2. 生成修复 SQL:
   
   对于缺少策略的表,生成:
   
   -- 启用 RLS
   ALTER TABLE table_name ENABLE ROW LEVEL SECURITY;
   
   -- 用户只能访问自己的数据
   CREATE POLICY "Users can view own data"
   ON table_name FOR SELECT
   USING (user_id = auth.uid());
   
   CREATE POLICY "Users can insert own data"
   ON table_name FOR INSERT
   WITH CHECK (user_id = auth.uid());
   
   CREATE POLICY "Users can update own data"
   ON table_name FOR UPDATE
   USING (user_id = auth.uid());
   
   CREATE POLICY "Users can delete own data"
   ON table_name FOR DELETE
   USING (user_id = auth.uid());
   
   -- 管理员全局访问
   CREATE POLICY "Admins have full access"
   ON table_name FOR ALL
   USING (
     EXISTS (
       SELECT 1 FROM users
       WHERE users.id = auth.uid()
       AND users.role = 'admin'
     )
   );

3. 创建测试脚本 /scripts/test-rls.ts:
   
   测试场景:
   - 创建两个测试用户
   - 用户 A 创建记录
   - 用户 B 尝试读取 → 应该失败
   - 管理员读取 A 和 B 的记录 → 应该成功
   - 输出详细测试报告

4. 输出内容:
   - RLS 审计报告(Markdown 格式)
   - 修复 SQL 文件
   - 测试脚本
   - 执行指南

请生成完整的审计和修复方案。
```

**验证标准:**
- [ ] 审计报告显示所有表都启用了 RLS
- [ ] 运行测试脚本，所有测试通过
- [ ] 在 Supabase Dashboard 的 Policies 页面能看到所有策略

**预计时间:** 2小时

## 🚀 阶段 3: CI/CD 自动化 (应该做 | 1天)

### ✅ 步骤 3.1: GitHub Actions 自动部署

**为什么要做:** 代码提交后自动测试和部署，减少人为错误

**复制给 Claude Code:**
```
任务: 配置 GitHub Actions 自动化工作流

要求:
1. 创建 .github/workflows/ci.yml:
   
   name: CI/CD Pipeline
   
   on:
     push:
       branches: [main, develop]
     pull_request:
       branches: [main]
   
   jobs:
     lint:
       name: 代码规范检查
       runs-on: ubuntu-latest
       steps:
         - Checkout 代码
         - 安装依赖
         - 运行 ESLint
         - 运行 TypeScript 类型检查
     
     test:
       name: 运行测试
       runs-on: ubuntu-latest
       steps:
         - Checkout 代码
         - 安装依赖
         - 运行单元测试(如果有)
         - 运行健康检查测试
     
     security:
       name: 安全扫描
       runs-on: ubuntu-latest
       steps:
         - Checkout 代码
         - 运行 npm audit
         - 检查依赖漏洞
     
     deploy:
       name: 部署到 Vercel
       needs: [lint, test, security]
       if: github.ref == 'refs/heads/main'
       runs-on: ubuntu-latest
       steps:
         - 触发 Vercel 部署
         - 等待部署完成
         - 运行冒烟测试(访问首页是否正常)

2. 创建 .github/workflows/scheduled-checks.yml:
   
   name: 定时健康检查
   
   on:
     schedule:
       - cron: '0 */6 * * *'  # 每6小时
   
   jobs:
     health-check:
       runs-on: ubuntu-latest
       steps:
         - 调用健康检查 API
         - 如果失败,发送通知

3. 配置 GitHub Secrets:
   
   需要添加的 secrets:
   - VERCEL_TOKEN
   - VERCEL_ORG_ID
   - VERCEL_PROJECT_ID
   - SENTRY_AUTH_TOKEN (可选)
   
   生成设置指南

4. 创建部署文档 /docs/DEPLOYMENT.md:
   
   包含:
   - 部署流程图
   - 如何触发部署
   - 如何回滚
   - 紧急情况处理

5. 输出内容:
   - CI/CD 工作流配置文件
   - GitHub Secrets 设置指南
   - 部署文档
   - 故障排查手册

请生成完整的 CI/CD 配置和文档。
```
