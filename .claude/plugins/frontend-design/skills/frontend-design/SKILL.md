# Frontend Design

For new designs or requested redesigns, understand the audience, purpose, and
constraints, then choose a coherent visual direction and implement a functional
interface. Use typography, color, spacing, and interaction deliberately; a bold
style is an option, not a requirement.

For routine fixes or extensions, use the project's existing components, tokens,
fonts, and layout conventions. Do not turn a functional change into a redesign.
Existing system fonts, solid backgrounds, and conventional layouts are valid
when they serve the product.

Prioritize correct behavior, accessible semantics, keyboard navigation, readable
contrast, responsive layout, and performance. Use motion only when it helps the
interaction, and respect reduced-motion preferences. Add fonts, dependencies,
or external services only within the authorized task and repository rules.

Validate the changed user flow as required by the repository; do not substitute
visual polish for functional validation or defer required checks to another request.
