## 契约与最小改动

复用 payment_orders、user_subscriptions、subscription_credit_grants、原商品表及原财务身份；
没有余额、会员状态或外部 ID 的第二权威。原 Stripe 列和发放幂等键不改；PR-2 接线前无业务映射写入。
只新增 payment_provider_refs：原单个 Stripe 列不能表达商品多渠道/周期 price 或约束跨商户对象冲突，
必须用有真实目标 FK 的窄映射。身份唯一键不包含 mode；mode 用于和目标原交易核对。
所有关联均 RESTRICT，不随主体或财务父行级联清除。共享商品映射不属于单个注销主体。

快照是严格字段白名单：契约版本、商品 ID/类型/更新时间、周期、币种和 major 单位、精确价格/折扣、
税处理、总积分/赠送。版本时间来自原商品 updated_at；PR-2 负责在锁内从服务端目录创建。
金额事实使用十进制字符串，支持有符号净额，unknown 为 JSON null，不转浮点、不猜精度或币种。
已有快照/原渠道/请求身份/主体及关联固定；新金额事实只允许追加，业务去重和回调接线由 PR-2 完成。
现有 JSON metadata 不扩成自由证据仓库。没有新增派生同步触发器、RPC、队列或设置入口。

映射仅 service_role 可 SELECT/INSERT，不能 UPDATE/DELETE；未来到期清理需授权的独立数据库路径。
普通用户保留原列 SELECT/RLS（含 account_open_required），新增商户/请求/快照等字段不可直接读；
旧表 service_role 权限保持，grant 新列仅补必要列权限。匿名、他人和封闭主体拒绝路径均实测。
`packages/db/schema.ts` 按其首行只作旧类型参考，迁移/baseline 是实际结构权威，本切片无 Drizzle 调用方。

迁移在事务内锁定三张原财务表，以目录指纹核对列、约束、索引、RLS、ACL、触发器和本次函数。

没有 IF NOT EXISTS 掩盖半应用结构、数据回填或旧外部身份猜测。锁等待 5 秒超时整笔回滚。

`node packages/db/tests/pay-common/run-local.mjs --local-only` 仅接受本机 Unix Docker socket，
不读数据库环境变量、不暴露容器端口、不下载镜像；使用仓库固定镜像及既有文件建库工具。
