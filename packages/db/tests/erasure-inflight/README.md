# 注销在途财务收尾：本机验证与回退

`node packages/db/tests/erasure-inflight/run-local.mjs --local-only`
仅接受本机 Docker Unix socket，使用已固定镜像、不拉取、不接受数据库 URL，
在一次性容器内从仓库文件建库。退出时删除本次容器和数据卷。
复用 B2a 的真实准入/预扣夹具、投影、金额、擦除屏障和确认/回执并发测试；
新用例覆盖禁用/封禁的允许与拒绝、原回执 hash、活动指针、批次发现/轮转/分页、
查询耗尽和三连接重复收尾。不调用供应商。

- `source-md5.json`：开工 staging `2259e8953bbfc60371ce891e0e847f6b5624c72d`
  文件建库后的五个原定义；0160 开头同时接受原定义和本迁移定义，其他漂移原子拒绝。
- `local-catalog-delta.json`：仅函数及新函数授权发生变化；无新表、列、账本或调度器。
- 每个迁移按原建库器规则重复，0160 再单独重放，并核对完整 catalog 一致。
- 先故意修改一个源函数验证防漂移，再验证无数据回退恢复完整 catalog，重新应用后测行为。
- 已出现 billing_pending 或已脱离活动指针的注销 cost_pending 时，回退脚本明确拒绝。

## 回退边界

`rollback.sql` 只是经本机验证的恢复材料，不是远程应用授权。
获准回退时先停止新宿主/cron 补偿接线、排空在途写入，再只读核对状态。
仅在脚本的保守检查通过时还原五个原函数并移除批次枚举函数；保留原有账户封闭、
证据、流水和终态，不恢复正文、token 或用户访问。
已经产生未知费用待维护事实时优先前向修复，不能通过回退重新要求已注销用户登录。
脚本不用于删除数据或释放未知费用预留。

## 与 PAYG 的边界

本次仍是 BILL2 v1。v2 合同/预扣不在当前 schema 中，不伪造 v2 PASS。
PAYG PR-A 接管原 0156 五个 `bill2_erasure_closed` 调用点（包括撤权），
并同步本次新增 `account_erasure_financial_batch` 的同一谓词调用及禁用/封禁 v1 绑定分支。
PR-A 必测已注销 v2 run 未发出的 call 撤权释放，以及 v1/v2 错绑拒绝与查询期限。
waiting_credits 接线归 PR-B。后合并方同步迁移编号和最新函数 MD5 后重跑共同回归。
