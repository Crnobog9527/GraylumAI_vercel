# 每周复盘中断后的收尾

这是本机合成数据测试，不连接 staging、不调用供应商、不读取项目环境文件。

```bash
node packages/db/tests/publish-monitor-interruption/run-local.mjs --local-only
```

套件从仓库文件建空库，使用真实 Runtime/BILL2 准入、领取、回执与结算函数。它在旧函数的事务内证明：
已扣 5 积分、被中断恢复释放的复盘仍停留在 claimed；恢复新定义后，验证同一运行单关闭、已用费用保留、
未发送调用的预扣退回、并发与重放不重复扣退、下周期可领取。未知供应商费用不会伪造：复盘先显示中断及
费用核对状态，现有 BILL2 收到晚到回执后结算一次，显示结果随账务状态更新。

截止时间由数据库判断：创建满 15 分钟且没有有效的 Runtime dispatch lease。既有 social-monitor 每 10 分钟调度，
下次领取时收尾；活跃调用保留其原有 lease。调度故障或批量积压仍会延后处理，不能把本机测试当成远程调度 SLA。

新应用只在 observe 返回 expired 时调用已有 runtime_cancel；不在持有复盘行锁的事务里获取 Runtime 行锁。
取消响应不确定就保留原领取，下次重试同一运行单。取消和写失败状态之间被部署中断时，下次 observe 也能根据
已终结的 Runtime 状态关闭领取，不建立第二份运行单。

0401 只替换两个函数，无表或数据转换。新旧应用可以兼容读取。需要恢复查询定义时执行本目录 rollback.sql，
保留所有复盘记录和原始账本；仍未明确的费用继续交给现有 BILL2 恢复。迁移由总控在 staging 上应用并核对。

CI 的现有数据库套件扫描器会自动发现本目录 run-local.mjs；单元测试覆盖调度端的分支与错误响应。
