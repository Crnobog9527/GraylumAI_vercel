# CORE-PATH-V2：新路径 100 人压测结果（2026-11-01 UTC，V2-13）

计划出处：`docs/launch/tasks/CORE-PATH-V2.md` 3.1、3.2。对照：`baseline-old-path.md`（旧路径，10-28）。单机 500/2000/5000 外推（3.3.3）这次没做。

**结论（先写）：** 新路径在 staging Micro 上 30 → 100 人六档共 1745 个回合，**0 失败、0 次 57014、账目全平、预占每档结束都归零**；数据库 CPU 均值最高 22.5%（线是 60%），锁等待 0（样本少）。
但 **整轮 p95 约 18.6 秒，没过"桩回复 + 2 秒（约 8 秒）"这条线**；这个延迟从 30 人到 100 人几乎不变（p50 15.0 → 14.6 秒），说明不是并发造成的，而是每轮固定多出约 9 秒——本批是从本机跑的，到 staging 每次请求往返约 0.13 秒，这很可能是主因，但**没有验证**，要在 Vercel 一侧再测才能判定。交换区在每档内部涨 53–251 MB、冷却后回到约 490 MB，按"不涨"严格算也没过。

## 3. 总控关心的几项

- **新路径回合失败率**：1745 回合 0 失败。
- **首字延迟**：p95 13.4–14.0 秒（桩的首字只有 1.5 秒），各档几乎不变；同样是固定开销，见第 4 节。
- **数据库往返**：回合相关函数每回合约 10 次（`pg_stat_statements` 差分，75–100 人档 10.0–10.1 次 / 回合），数据库内耗时每回合约 39–42 毫秒（`turn_open` 约 11 ms、`turn_close` 约 10 ms、`turn_call_begin` 约 2.8 ms / 次）。第 2 档 11.7 次、186 毫秒，是资料库和会话列表函数首次调用较慢混进来了。应用到数据库的 HTTP 请求总数这次没有量到。
- **锁等待**：没看到（见上）。
- **daily_spend 预占**：每档结束 `reserved_usd` 全部为 0；每回合对 `daily_spend` 更新约 2 次（855 次 / 428 回合），全是 HOT 更新，落在同一天的 16 个桶行上——这是共享热点行，但本批没采到 tuple 等待。
- **profiles 热点**：每回合更新 `profiles` 约 2 次（862 / 428），99% 以上是 HOT 更新，每个用户自己一行，不是共享行；没有 tuple 等待。
- **账目**：每档结束 100 个账号的余额都等于最后一条流水的 `balance_after`，负余额 0。积分净变化：第 1 档开户赠送进账，其余档按回合扣（聊天 2、教练 10 积分）。
- **日限**：本批桩计的 `spent_usd` 合计约 31.6 美元（各档 2.23 / 3.88 / 5.42 / 7.44 / 4.19 / 8.39），记在止损账上，对应 300 日限；没有真实模型花费。

## 4. 每轮核·秒 k 与那 9 秒是哪来的

k（节点 CPU 均值 × 2 核 × 150 秒 ÷ 完成回合数，含资料库读取和库的后台进程）：0.167 / 0.213 / 0.171 / 0.158 / 0.199 / 0.138 核·秒 / 轮（第 1–6 档）；100 人两档平均约 0.15。每档 23 个 CPU 点，量级参考。旧路径基线估的是 1.5–2.1 核·秒 / 轮（样本 2–4 点），3.3.1 的假设是 1.15。

延迟的固定部分：聊天一轮的桩只要约 6–7 秒，实测 p50 15 秒，首字 p95 13.5 秒（桩 1.5 秒首字）。这部分不随人数变化。本机到 staging 的 REST 请求测了三次，往返 0.13–0.39 秒。**只是推测：**一轮要顺序打几十个 HTTP 请求，加起来就是这个量级。没有应用内分段计时，所以没法把它拆成"网络"和"应用"。验证办法：在 Vercel 同区域（pdx1）跑同一套，或在应用里加分段计时再跑一档。Vercel 一侧要用桩需要桩有公网地址，这需要总控 / Owner 决定。

## 6. 没测到什么 / 不确定

- 延迟线：本批从本机跑，不能代表 Vercel 到数据库的链路。
- 限流：Redis 是假的，限流开销没测。
- 采样：等待事件每档只有 120–440 个活动后端样本（第 1 档 0），锁等待"没看到"不等于不存在；CPU / 内存 / 交换区是节点级、10 秒一点。
- 单个 100 人批次、一台 Micro，没有重复。
- 驱动缺陷已修（#1589）：资料库读取原来只带令牌，tRPC 要 cookie，第一次开跑的 30 人档因此作废重跑；账号文件新增可选字段 `cookie`。
- 本批的会话和草稿由本机脚本用账号自己的令牌建（`runtime.start`、`opc.start`），脚本不进仓库，做法写在 README。
- 测试账号 loadtest211–310 留在 staging（未封禁），积分还剩约 39 千；窗口、`system_settings` 都没动。日限 300 需要总控调回。
