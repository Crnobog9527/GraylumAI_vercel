# REPORT-GEN：报告结束即时结算（#1453，high）

## 目标与完成标准

停止或失败使报告执行结束后，在服务端同一事务内按 0295 的既有规则结算固定报告费，不依赖页面 report.status 或每日补结算。停止退款、重复停止、并发状态查询/每日结算只退一次；完整报告仍收 500。保持 profile → report_fees 锁顺序、幂等和 REPORT_FEE_CONSERVATION。

不更改价格、产品规则、前端或凭证；不写 staging 数据库/配置，不合并，不结算历史挂账，不调用付费模型。

## 实现选择

评估过在 TypeScript 停止/失败分支调用现有 report_fee_settle，但这不能覆盖 SQL 内部执行结束（runtime_execution、runtime_financial_recovery、恢复任务及删除路径），多个入口逐个接线仍有遗漏风险。现有表和结算函数已足够，不增加表、队列或服务。

0397（总控于 2026-10-26 分配）新增 AFTER UPDATE OF state,result 触发器，仅对 completed/cancelled/cost_pending 且报告费仍 held 的执行调用 report_fee_settle_internal。数据库没有 failed 状态；失败最终走 cancelled 或不完整 completed。原结算函数全文已核对 packages/db/functions/report/report_fee_settle_internal.sql，本 PR 不修改它，不采用读取旧函数文本再替换的迁移写法。

- 完整报告按原规则收费；未完整的已结束报告退款；cost_pending 且未完整仍 held，后续结束再结算。
- 触发器不提前锁 fee，原函数依次锁 profile → fee，仍做守恒检查；异常不吞掉，执行状态和退款同时回滚。
- 既有页面查询及每日补结算保持幂等；普通执行和已结算报告不会通过新触发器加钱款锁。
- 新旧服务端兼容同一 RPC。迁移重复执行只重建同名触发器/函数，不回填或重结历史数据。
- 回退只删除新触发器及其函数，保留全部报告费、余额和账本，继续使用旧查询/每日结算；已退款或收费不逆转。具体 SQL 在迁移注释。

## Validation handoff

由总控核对 0396/0397 迁移顺序、按工程规范上库和比对指纹后再合并；本窗口不写 staging。

入口：https://auth-staging.graylum.com。运行 `node ~/.graylum/staging-login user2`，用生成的 storageState 打开浏览器；过期就重跑；不读取、不记录凭证。实际生成会调用付费模型，执行前由总控指定测试预算；本任务没有申请或消耗预算。

1. 在可生成报告的已确认定位中记下余额，生成报告，确认 500 固定费冻结（模型临时冻结单独核对）。
2. 生成未完整时停止；关闭/离开报告页，不再调 report.status。由总控只读查询执行状态及报告费；执行进入 cancelled 或不完整 completed 的同一次停止/结束请求完成后，固定费必须 refunded，charged_credits=0，余额退回 500。
3. 重复停止、刷新状态并与补结算重叠，报告费 release 仅一条，余额不再增加。
4. 独立生成完整报告，固定费 charged=500，刷新和重复结算不改变金额。
5. 不在范围：生产、真实付款/退款、改设置、充值、历史挂账手动结算。未经总控批准不删除记录或强制修改状态。
