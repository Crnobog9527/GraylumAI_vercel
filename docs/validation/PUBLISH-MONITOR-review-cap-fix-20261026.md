## 冻结与请求

- 复盘的输入/历史预算不再被普通聊天配置覆盖；输出上限取复盘、模型、批准报价中的最小值。没有全局 purpose 配置时也冻结复盘输入限制。
- 排除复盘的聊天 Skill 目录、资料检索及研究工具扩展；真实会话类型仍是 positioning_draft，工具保持 read_source。
- 复盘使用已有 PAYG 档案批准的供应商默认请求格式（parameter: none，即不传 reasoning 覆盖字段）。当前 interactive=low 在1000输出下会被现有4096校验拒绝；这里不改后台配置、不放宽普通聊天校验。PAYG 的用途/线路/格式/思考变体批准仍必须通过。
- 单次上限 = openRouterCallBound(原批准单价，冻结输出，min(复盘输入、报价输入、PAYG maxBytes) + 原 PAYG templateTokens + marginTokens)。整数精算，缓存写入价取较高值，向上取整12位。
- 原 callPolicy 的 upperUsd、providerLimits、PAYG 档案不降低。把单次上限 × 可容纳调用数冻结到 BILL2 limits.costUsd / maxCalls / maxPreDeduct；BILL2 input 同时保存相同的上下文限制。每次实际请求仍按原链路生成并冻结独立调用报价，SQL核对公式和整单余额。
- 执行前以最终序列化请求检查字节容量；真实 SDK 的 max_tokens=1000。重放沿用原执行，不重算旧报价或重试供应商。
