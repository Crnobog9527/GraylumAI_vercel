# PAY-COMMON：支付渠道版本冲突修复

风险：high（后台支付渠道设置）。依据 #661 最后两条重验评论及 #668 合并后的缺陷。

目标：旧版本保存立即返回 CONFLICT/409 并显示原冲突提示；任何其他失败、超时或未知结果
结束保存中，提示先重新读取，且重新读取可用。保留版本保护、批量原子性、渠道与新购买的互斥。

范围：触发器冲突错误码、服务端映射、渠道卡片等待与恢复，以及对应回归测试。
不访问远端数据库、不改平台配置、不合并；完整 CI 后转 ready，处理独立审查并交主窗口。

## 调查

- 0173 触发器使用 SQLSTATE 40001 表达不可重试的业务版本冲突。
- 锁定版本的 Supabase 客户端仅对幂等请求重试；POST upsert 不自动重试。
- 应用的 Runtime budget transport 没有写入重试；tRPC mutation 默认无重试。
- Upstash analytics 通过 pending 后台 promise 记录，错误被捕获；中间件不等待 pending。
  因此该警告本身不证明它导致了冲突请求超时。
- [Supabase 官方故障说明](https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b)：
  PostgREST 14 会重试人为抛出的 40001；业务冲突应使用 PT409。
- 本机 PostgreSQL 17 + 仓库固定 PostgREST v14.13 复现：旧触发器的一个 HTTP 请求在
  1000ms 内重复执行 1943 次后仍未返回；PT409 后一次执行，10ms 返回 409。
  12 个同版本并发请求：1 成功、11 冲突，最大 26ms；混合批量冲突全部回滚。
  计数器仅存在于一次性本机测试库，利用序列不随回滚撤销证明重复事务。
- 上述重试发生在 PostgREST 服务端，不是 Supabase JS、我们的代码或前端重新提交。
  无购买/其他写入的本机复现已经出现，因此不需要锁竞争也能触发。原有事务锁保留，
  有真实未提交购买/保存时仍可等待它；不绕过互斥或伪造“冲突”。
- 远端 PostgREST 版本、当时锁持有者与 Vercel 逐请求因果链未核实；不能断言所有
  middleware 500 都由同一原因引起。本次消除已复现的冲突重试路径，并兜住其他失败。

## 修复与兼容

新增 0175，只把渠道 guard 的业务冲突 SQLSTATE 改为 PT409；保留锁、版本校验、权限和批量事务。
API 同时识别 PT409 与旧 40001，但只有应用迁移后才能消除 PostgREST 的内部重试。
旧 API 不认识 PT409 时仍会安全拒绝，但显示通用错误；发布与迁移应协调执行，随后重验。
恢复使用前向修复；不恢复 40001，不删除设置、订单或版本。没有新增表/RPC/服务。

前端保存与确认读回共用 10 秒上限，重新读取也有 10 秒上限。失败时解锁重新读取，保持编辑锁定，
只有明确的新读取成功才恢复编辑。不自动重试 mutation；离线不排队等待自动提交。
迟到的 mutation 结果不更新成功状态或发起确认读取。超时不代表服务端取消，仍以实际读回为准。
目录统计独立刷新，不再用它的完成状态判定渠道保存完成。

## Validation handoff：重验 #661 第 4 步

由主窗口安排 0175 应用和本 PR 部署，本窗口不执行。先确认域名绑定的部署包含本 PR，
且迁移已到位；旧部署/旧触发器的结果不能当作此次修复通过。

1. 两个测试管理员标签页 A/B 打开 `/admin/settings` → 积分计费，分别重新读取，确认同一渠道。
2. A 改为另一渠道保存并等待确认。B 保留旧页面，不先刷新，选择另一渠道保存。
3. B 应迅速得到 HTTP 409 / CONFLICT，出现“这个设置刚被其他人改过……”；无自动重试或成功提示。
   保存与编辑锁定，“重新读取”可点击；点击后读到 A 的值，恢复编辑。
4. 交换渠道方向再测一次。记录两次耗时、响应码、文案及重新读取结果，确认旧版本未覆盖。
5. 浏览器拦截保存响应模拟 500/丢失响应/持续挂起：立即失败或最多 10 秒后退出保存中，显示
   “没能确认这次保存是否生效。请先点‘重新读取’查看当前实际设置，再决定是否重新保存。”；
   重新读取可用，失败仍可再次读取。读回前不能重新保存，也不能自动补发。
6. 同样检查保存成功但确认读取失败/挂起；恢复网络后重新读取实际值，再由管理员决定是否保存。
7. 最后恢复主窗口指定渠道，两页重新读取确认。浏览器不发起真实购买。
