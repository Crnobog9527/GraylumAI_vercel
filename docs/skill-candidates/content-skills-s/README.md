## 四个包

| 包名 | 用途 | 触发意图（写在 description 里，匹配器只看 name 和 description） | 要读的上下文（宿主提供） | 产出格式 |
| --- | --- | --- | --- | --- |
| `short-video-script` | 视频口播稿，连同标题、封面字、发布文案和话题标签 | 写 / 改口播稿、视频文案、脚本、台词、开头；"改短一点""更口语" | 定位、选题简报、已保存的稿子（如有） | 一句话说明 → 标题 2–3 个 → 封面字 → 分段正文（标秒数、总时长、替换开头）→ 需要补的真实素材 → 发布文案和标签 → 下一步 |
| `video-storyboard` | 分镜：每段口播配什么画面、怎么拍、多长 | 出分镜、分镜脚本、这段拍什么、怎么拍 | **已定稿口播稿**（声明来源 `script`）、选题简报 | 一句话说明 → 分镜表（镜号、时长、对应口播原句、画面怎么拍、素材道具）→ 拍摄顺序 → 准备清单 → 新手提醒 → 下一步 |
| `video-editing-guide` | 剪辑建议：开头、节奏、画面切换、字幕、声音 | 出剪辑建议、怎么剪、字幕和音乐怎么弄 | **匹配当前口播稿的已保存分镜**（声明来源 `storyboard`）、定稿口播稿、选题简报 | 一句话说明 → 整体风格 → 逐镜剪辑表 → 剪辑步骤清单 → 封面 → 发布前检查 → 下一步 |
| `post-and-article` | 图文笔记、多图帖子、长文章、短帖 | 写笔记、图文、轮播帖、公众号 / 知乎文章、改标题、正文太长 | 定位、选题简报、已保存的稿子（如有） | 图文：说明 → 标题 → 图 1–N（画面、图上文字）→ 正文 → 标签 → 真实素材 → 下一步；长文：说明 → 标题 → 带小标题的全文 → 真实素材 → 下一步 |

四个包的共同规则：信息够就先写、缺关键信息才问一个带例子的问题；一条内容只做一件事；不编造用户的经历和数据，用【】留给用户填；国内平台不站外引流、不用绝对化用语、提醒版权和隐私；不承诺播放量；跟用户用他的语言聊，内容按目标观众的语言写；不说"已保存"，保存由用户在界面确认；对应的另一个 Skill 没加载时只提议下一步，不越界代写。

## 包结构和声明字段

- 每个包：`SKILL.md`（对话时加载的唯一文件，自成一体）+ `EVALS.md`（验收用例，不进对话）。管理员发布时每个文件的 `requires` 为空（`modulePublication.ts`），所以不放需要另外读取的参考文件。
- 不带步骤、不开强引导；后台"与社交媒体相关"四个都勾上（POSITIONING-GATE 用），都不是定位类。
- 分镜、剪辑建议的内容来源字段（`contentSource`）和其余固定字段，按 G / A2 定稿的规则声明；在 `workflowManifest.ts` 支持之前，这两个包只发布 `SKILL.md`，Skill 正文里已写明"没有定稿口播稿 / 分镜就不写，并请用户先完成上一步"。字段补上后重新登记哈希。

## 发布到 staging（由总控安排）

1. 用后台现有的管理员 Skill 包发布，每个目录（目录名等于 `name`）上传一次，生成新的不可变版本。
2. 在后台给四个模块勾选"与社交媒体相关"，不开强引导。
3. 发布后从 staging 读回逐文件哈希，和 `file-hashes.json` 核对。
4. 真实模型行为（按意图匹配和四个包的产出）在 #621 第 11.3 节付费小评测和 staging 验收里跑，之前一律 NOT_RUN；按意图加载要等 A3 合并后才会在对话里生效。
