# Agent 指挥手册（单一自然语言模式）

## 1) 目标
你不写代码，只下达任务。Agent 必须按固定格式给你结果，且每次要可验证。

## 2) 唯一指令模式（自然语言）
你只需要用自然语言说需求，不需要懂代码，不需要写结构化模板。

Agent 的职责：
- 自动理解你的目标。
- 自动补齐实现细节（涉及页面、接口、数据、测试）。
- 如果信息不完整，先做合理假设并执行；只有高风险时才向你确认。
- 全程用你能看懂的中文回报结果。

你可以直接这样说：
- `把聊天页按钮文字改一下，更像产品级。`
- `用户反馈积分扣错了，请你定位并修好。`
- `我要加一个功能：用户能导出最近7天聊天记录。`
- `帮我检查这次改动会不会影响线上稳定性。`

## 3) 你要求 agent 每次固定输出格式
每次都必须包含：
1. 改了什么
2. 为什么这么改
3. 影响哪些页面/API/表
4. 怎么验证（命令或步骤）
5. 剩余风险

你可以直接附加这句：
`输出请严格按“改动/原因/影响/验证/风险”五段给我。`

## 4) 四种高频任务模板

### A. 新功能
`我要新增[功能]，你按现有架构自己补齐细节并实现，最后给我可验证结果。`

### B. 修 Bug
`请定位并修复[现象]，优先给根因，不要仅做表面补丁；修复后给最小回归测试。`

### C. 线上排障
`请按“现象->根因->修复->验证->回滚点”流程处理；先给止血方案，再给长期修复。`

### D. 发版前检查
`请执行发版前检查：测试、构建、关键路径冒烟（登录/聊天/积分/管理后台），并输出阻塞项清单。`

## 5) 禁止项（你要明确告诉 agent）
- 不得改动聊天旧链路为主链路。
- 未经确认不得改数据库结构和 RLS。
- 未经确认不得跳过测试直接宣称完成。
- 不得把密钥写进代码或文档。

## 6) 本项目的“正确技术入口”口令
需要聊天能力时，你可以固定说：
`必须走现行主链：chat/page.tsx + useStreamingChat + /api/ai/stream，不要用旧 chat.sendMessage。`

## 7) 协作验证样例（已完成）

### 样例 1：自然语言
任务：清理 `.env.example` 中真实密钥样式值。
结果：已改为占位符，无真实密钥样式值。

### 样例 2：自然语言
任务：修复 `admin.getUserDetails` 消息统计。
结果：已改为按用户 conversation IDs 统计 messages，并通过 API 单测基线。

## 8) 你可以复制即用的指令结尾
`完成后必须给：改了什么、影响范围、验证结果、剩余风险；没有测试结果视为未完成。`
