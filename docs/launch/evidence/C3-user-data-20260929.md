## 口径与边界

- 本机静态提取：75 个唯一迁移 CREATE TABLE，32 个 schema.ts 表声明，并集 91 个。本表逐一纳入，包括共享配置、间接用户归属和可能混合个人数据的系统表；不是声称 91 张表都已在线创建或每行都有个人数据。
- `M` = 有迁移 CREATE；`S` = 仅 schema.ts 有 CREATE 等价声明，迁移可另有 ALTER/引用但没有 CREATE；`M+S` = 两边均有声明。下表主外键采用 M 定义；S 外键仅是 Drizzle 声明。后续 FK 增补另列，不能只用 CREATE 时点断言最终结构。
- 未写 ON DELETE 的 SQL / Drizzle 外键标为 **NO ACTION**。RESTRICT 单独保留，不能当 CASCADE。这里的删除动作描述父行被删时对子行的行为。无 FK 不等于无关联；UUID、JSON 内 ID、数组仍可承载用户归属。
- “未见”限于迁移范围中的触发器检索，绝不等于线上没有；权限、RLS、NOT NULL/CHECK、其他行的反向 FK 还可能拒绝删除或置空。所有表的反向引用可由下面完整 FK 清单反查。
- “同一行”依据列定义表示承载能力；metadata/payload/result 等自由 JSON 不能据结构证明没有正文。无金额列的内容表仍可能在 JSON 中包含成本。
- 下表证据简写 `S:L` = `packages/db/schema.ts:L`，`NNNN:L` = 后文对应迁移路径第 L 行。所有路径都以本基线为准。表行的源位置给出 CREATE/pgTable 起点，其紧邻定义同时支持字段与 FK；触发器代码见 D/U 清单。
