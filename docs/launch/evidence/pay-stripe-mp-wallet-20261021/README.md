# PAY-STRIPE-MP 钱包会员修复（2026-10-21）

## 目标与边界

修复 Owner 指定的四项：钱包升级被当成卡取消续费、升级后同时显示 Pro/Gold、钱包会员 Stripe 收据无法核实、取消或失败时误带国际银行卡提示。钱包同等级改年付及提前续买须先核对产品规则，缺口交总控问 Owner，不能自行制定。

## 规则核对及待总控确认

依据 `docs/launch/MASTER_PLAN.md` 第 2.1 节第 51 项、`docs/launch/design/paywall/README.md` 第 11–12 条及 v25 定稿：

- 钱包为一次性付款，不自动续费；不能把 `cancel_at_period_end=true` 解释成银行卡取消自动续费。
- Pro 可随时升 Gold，按 Gold 付款后立即生效，原积分保留；原 Pro 年付尚未发放的积分继续按月发完。
- 钱包到期可重新购买；创始会员可在到期前或到期后 7 天内续买一年。
- 本人账单凭证由原收款方提供。
- **BLOCKED（产品规则）**：未找到同等级普通钱包月付改年付、有效期内提前续买的生效日期及剩余期限规定。需总控问 Owner：新期限从付款日还是原到期日开始，原剩余期限是否保留，积分从何时发放；不能套用银行卡套餐变更或 Pro→Gold 规则。建议保留已付期限，由原到期日接续年期；这只是待决定的建议，未写成批准规则、未开放该流程。

## 实现与原因

1. 在原 `pay_common_membership_facts` 的受控 JSON 投影中加入原订单的付款方式；钱包显示 active，不再触发“先恢复续费”提示，卡的停止续费判断保留。该提示原先来自旧资格矩阵，钱包升级本身已有受控 transition。
2. 订阅摘要仅突出当前最高等级。隐藏旧 Pro 只影响显示，订单、会员期限和积分发放均保留。
3. `resolveStripeOrderIds` 原先要求所有内部会员都有外部 Stripe 订阅映射；钱包只有单笔 Checkout/PaymentIntent，因此抛错，积分包则不经过该映射要求。钱包现在由原单笔会话读取 Stripe 收据，保留商户/模式/订单/本人/金额/币种核验；银行卡仍要求其订阅映射。
4. 返回页由服务端报告实际付款方式，只有 `card` 显示国际卡的大陆提示；微信、支付宝、大陆卡和未知方式不带该提示。已付或待人工核对的付款仍显示真实状态，不错误承诺“没扣费”。
5. 为满足支付宝 Fail 验收，在原 service-only `pay_waffo_observe_qualification` 增加 `failed_unpaid`，同锁关闭未付资格并标记异步失败。页面显示失败，仍保留底层 pending 供迟到款进入人工核对，不授予会员或积分。

独立审查第一轮发现额外查询私有列和直接写失败列的权限问题；均已删除，改为复用现有受控函数，没有扩大表或列权限。

## 迁移、兼容与恢复

暂用 `0329_pay_wallet_membership_projection.sql`（当前基底至 0328，最终编号由总控核对）：只修改两个函数体，无表、列、ACL 或历史数据变更。未知函数体会拒绝应用，支持重复执行。

必须先应用 SQL，再更新应用。旧应用忽略新增 JSON 字段，旧 `closed_unpaid` 调用继续有效。应用回退时可保留 SQL；若需数据库修正，以前向修复这两个函数为准，不能删除订单或积分。迁移只增加投影与有界失败状态，没有需要回填或恢复的数据。
