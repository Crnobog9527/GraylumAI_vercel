## 最小实现

复用已有 cron、BILL2 和 epoch 保护的 owner_cancel；新增一个仅 service_role 可执行的 RPC，
在数据库中筛选并加锁复核原执行，不开放底表权限、不新增表或后台调度。
两处现有准入检查识别服务端已释放的失败标记，避免保留退款资格的旧回合继续挡住新输入。
已结算研究调用不参与模型正文重建；未结算调用和模型原 HTTP 窗口继续受保护。
服务端只选取已超时、无未知费用的 v2 interrupted 执行，按原 epoch 加锁复核；
已扣费 PAYG 只释放 Session 并更新 epoch，保留未知故障的原 24 小时退款资格，
不伪造用户取消。未扣费执行复用 owner_cancel；未完成报告按既定固定价规则退款。
新 epoch、仍活跃请求、等待用户续接/积分、停止意图、容量拒绝和已终止结果均不能被越权取消。
保留研究结果、原账务与正文检查点；自动恢复不运行 SDK、不发起模型或研究供应商请求。
补充仅含固定错误码和标识符的失败/恢复日志，不记录正文或密钥。

- 回退时先回退服务，再删除新增函数；迁移不转换或删除已有数据。已收口的账务保留，
