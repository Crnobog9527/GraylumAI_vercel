## 结论

**本轮不建议采用更高思考强度。** 新试验中 medium 最好（24/30），仍未超过第二轮基线（25/30）。
low、high 均为 23/30。medium 单次费用增加 8.1%，供应商 latency 增加 27.2%；high 更贵、更慢，质量未改善。
这只是同一组固定输入、每档每题一次的探索性试验，不能证明档位的普遍优劣；不重试、不补样。
产品档位及 PAYG 配置没有改动。如后续考虑采用，由主窗口另行安排准入采样并请 Owner 决定。

## 耗时解释与局限

费用、reasoning tokens、供应商 latency/generation_time 均为实际记录；历史基线与本轮统一通过 generation API 读取耗时。
表中 latency 是 OpenRouter 返回的原始毫秒字段，不等同于用户端完整耗时；不把 latency 与 generation_time 相加。
平均 generation_time：基线 3.608 s、low 2.463 s、medium 4.348 s、high 4.790 s。
本轮客户端完整耗时均值 / P95（最近秩法）：low 2.757 / 4.334 s、medium 4.631 / 11.368 s、high 5.091 / 12.686 s。
旧样本未保存客户端完整耗时，不能给出该口径的前后增幅。不同时间段、顺序执行、缓存命中及供应商负载会影响费用和耗时。
旧评分保留原锁定结果，新评分由独立上下文完成，因此存在评分者差异；未对旧输出重新评分。
固定输入试验不衡量三轮新输出递推后的端到端效果，也不替代产品准入或 F1 联合浏览器验收。

输入/缓存写 $0.25/M、输出 $0.75/M；当前目录价格及阶梯均在该上限内。
单次预留按“完整请求 UTF-8 字节数 + 8192”个输入 token 上界、2048 个总输出 token 计算，不预先抵扣缓存优惠。
每次发送前检查已结算纳美元 + 未结算预留 + 本次预留 ≤ 1,000,000,000；只有已知官方费用才能释放差额。

认证、传输、HTTP、未知费用、超预留或未知完成状态会停止；已知费用的截断/坏 JSON 计失败样本，继续剩余既定样本，不替补。
