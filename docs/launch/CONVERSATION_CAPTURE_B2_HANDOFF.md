## 改动与启用

B2 在 OPC 导师准入传入 H1 已导出的 `hostTurnContextSchema`，固定 system 提示词使用
`HOST_TURN_DATA_NOTICE_V1`。新请求因此采用现有 `scope-projection-v2` / `host-turn-v1` 路径；
既有 H1 的块宽、预留、缓存资格、价格校验、实际请求容量与 hash/claim 顺序不变。
整个步骤清单及受保护状态来自冻结材料，实际字段值不塞进 system。整理器输出 `patches` 和空 `notes`，
复用 B1 的 `opc_capture_apply`，跨步骤提取；手改、继承及确认内容继续只能生成更新建议。

导师不再被当前题号限制；宿主以第一个必需缺口、否则第一个未确认字段、否则最后字段确定 task。
卡片回答继承原卡 task。每步开场使用该步首字段的确定性请求标识，同一步/轮次只开场一次。
旧请求优先精确重放；B2 服务端焦点变化时，只通过既有权限 RPC 取回冻结 task，再交给原 SQL 做完整比较。
旧 v1 请求不能借此放宽比较，用户输入等其他字段仍必须一致。
