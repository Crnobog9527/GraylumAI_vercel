## 1. 什么是"平台创作 Skill"

后台发布的、**不是定位类**的 Skill（口播稿、分镜、剪辑建议、图文 / 文章，以及以后同类的）。

- **定位类**不是后台开关，由 `workflow.yaml` 的结构决定：每一步都声明了问题、且至少一个问题带 `profileKey`
  （`isPositioningWorkflow`，和数据库 `opc_is_positioning_workflow`、`opc_information_schema` 同一条规则）。
  只有定位类按步骤强引导（提问卡、每步确认、每轮自动整理）；其他 Skill 写的步骤只作为给 AI 的工作顺序（G，#1026、#880）。
- 后台 Skill 编辑页会标明这个 Skill 是不是定位类；"每步都有问题但没有 `profileKey`"的会标出来请管理员确认。

## 2. 触发规则

### 2.1 在哪里加载

| 窗口 | 平台创作 Skill 怎么进来 | 不在本文 |
| --- | --- | --- |
| 自由对话 | 按意图自动匹配；或用户直接选中某个 Skill | — |
| 选题窗口（一个选题一个会话） | 按意图自动匹配（B1 页面接入后）；或回复下的提议按钮（A3） | — |
| 选题讨论窗口 | 现状：用采用时固定的定位方法版本写选题；按意图加载其他 Skill 随 P3 再接 | 选题生成本身 |
| 定位 | 不加载平台创作 Skill | 定位流程 |
| 报告、整理纪要、定位导师 | 不加载 | 各自宿主 |

### 2.2 按什么选

- **只看公开信息**：匹配调用的输入只有用户这句话和每个候选 Skill 的公开名称、简介（来自 `SKILL.md` 开头的 `name`、`description`）。
  简介和用户原话都当数据，不当指令。**以后换内容时，`description` 就是触发条件**：写清"用户说什么时用我"，例如"用户要写短视频口播稿、
  改口播稿时使用"。不按关键词或正则判断（ENGINEERING 第 6 节）。
- 匹配由模型判断，返回候选之一或"都不用"；"都不用"就按普通对话回答。
- 用户直接选中某个 Skill 时不发匹配调用，直接用它。

### 2.3 多个同时命中

- **现在**：每轮最多选一个（`{"key":"candidate-N"}`）。
- **A3 之后**（开工前置设计第 8.1.1 节）：一轮可以选最多 3 个，按匹配返回的顺序一起用；几个 Skill 的正文按顺序拼进同一次正文调用，
  放不下时只保留排在前面的，并在执行记录里写明舍弃了哪些；"当前这组 Skill"在用户没明确换任务时保持不变。
- 同类 Skill 不要发布两个都想接同一类请求的版本（例如两个"口播稿"）：匹配只能二选一，结果不稳定。换版本走第 4 节的替换，不并存。

### 2.4 什么情况不加载

- 模块没启用，或用户看不到（`userVisibleModules`）；
- Skill 是定位类（只从定位入口开始；在自由对话候选里去掉它由 A3 完成）；
- 包声明了旧式 `tasks`（必须选任务的包不进自动匹配）；
- 模块勾了"与社交媒体相关"、而用户还没有已确认的定位：不进候选；用户直接选中时按 POSITIONING-GATE 拦截，不扣积分（#831、#900）；
- 这个 Skill 连同用户这句话放不进它自己的模型容量（准入时估算，放不下就从候选里去掉，不为它付匹配费）；
- 整理纪要、报告、定位导师这些宿主回合。

## 3. 调用规则

### 3.1 能读什么

| 上下文 | 什么时候读 | 怎么读（现有机制） |
| --- | --- | --- |
| Skill 自己 | 每次选中 | `SKILL.md` + `workflow.yaml` 步骤的工作顺序；直接选中时另带步骤声明的资料文件（最多占 1/4 容量，放不下就退回只带 `SKILL.md` 和工作顺序）；自动匹配时不带资料文件 |
| 定位 | 选题窗口：每轮常驻（绑定的已确认定位版本的档案）；自由对话：模型按需调用 `read_source` | `runtime_scope_material`（A1 起只含定位档案 + 本选题类型、标题、简报）；`runtime_workspace_source` |
| 选题 | 选题窗口：本选题的类型、标题、简报常驻 | 同上；读不到别的选题 |
| 资料库文档 | 用户在这一轮引用了文档时 | LIB-4b（默认关闭，开关打开后生效） |
| 衍生内容来源 | 只在选题窗口、只在声明了 `contentSource` 的 Skill 被选中的那一轮 | A2：数据库在同一事务里选版本、核对可用性、记录并返回正文；正文只放进这一次调用，不进之后的历史 |
| 已保存的其他稿件正文 | 不读 | 常驻材料里没有正文（A1） |

- 所有读取都走现有可用性检查（`opc_source_allowed`、`opc_content_allowed`、`runtime_history_available`）。来源被撤销或删除后，
  读过它的回复按依赖链一起不可用；删除稿件会抹掉读过它的回合（A2）。
- 衍生内容来源：`script` 读本选题最新的、可用的定稿口播稿；`storyboard` 读最新的、可用的分镜，而且它必须基于当前定稿口播稿，
  否则这一轮以固定提示结束（"当前分镜基于旧版口播稿，请先更新分镜……"）。自由对话里不注入，Skill 按用户给的内容写。

### 3.2 产出写到哪里

- Skill 只产出这一轮的回复。**Skill 从不自己写入任何用户数据**。
- 保存都要用户确认：选题窗口存为口播稿 / 分镜 / 剪辑建议 / 正文（`opc_content_versions`，分镜和剪辑建议的来源由数据库按生成回合的注入记录决定，A2）；
  其他对话存进"本对话成果夹"（C1）；纪要只复制和导出（Q1）。AI 可以提议保存（A3 的 `save_content` 信号），用户点确认才写。

### 3.3 计费（沿用现有口径，不为 Skill 另设价）

- 按实际调用的模型费用边用边扣（BILL-PAYG）；Skill 本身不加价，用的是模块配置的对话模型。
- 自动匹配：匹配调用是一笔（阶段 `skill_matching`），正文调用是一笔（阶段 `skill`），同属这一轮的运行单。
- 在任何调用之前就被拒（POSITIONING-GATE、直接选中时来源缺失或放不下、积分不足）：不扣积分。
- 自动匹配之后才发现来源缺失、不匹配或放不下：匹配调用照常按实际费用结算，正文调用不发生（开工前置设计第 2.4 节）。

## 4. 替换规则

### 4.1 Skill 包必须声明的固定字段

以后换内容只改正文和资料文件，下面这些保持不变：

| 位置 | 字段 | 平台创作 Skill 的固定写法 |
| --- | --- | --- |
| `SKILL.md` 开头 | `name` | 和后台"Skill 名称"、目录名一致，换版本时不改 |
| `SKILL.md` 开头 | `description` | 触发条件（第 2.2 节）；可以改写措辞，但不要改它负责的那一类请求 |
| `workflow.yaml` | `kind` | `document` |
| `workflow.yaml` | `steps` | 至少 1 步（`title` + 非空的 `resources`，一般写 `[SKILL.md]`）；**不写 `information` / `profileKey`**（写了就可能被当成定位类） |
| `workflow.yaml` | `contentSource` | 只给衍生内容 Skill：分镜写 `script`，剪辑建议写 `storyboard`；其他不写。值只能是这两个，新增别的值要改代码和数据库 |
| 后台模块 | 对话模型 | 管理员在后台选；换内容不必改 |
| 后台模块 | "与社交媒体相关" | 新建模块时选；平台创作 Skill 都选"是"（#831）；之后在单独的设置卡里改 |

- 包里不要写别的字段：`workflow.yaml` 的解析是严格的，未知字段会让发布失败。成果类型目前没有字段（C1 实施时如需要，按本表追加一行）。
- `organizerTemplate` 只对定位类有意义，平台创作 Skill 不写。
- 包里只能放 Markdown 和 YAML，不放可执行文件（后台导入时拒绝）。

### 4.2 怎么发布

1. 管理员在后台打开这个模块，导入新的 Skill 文件夹（同一个 `name`），发布。
2. 发布是一次原子写入：生成新的不可变版本（版本号 +1），模块从这一刻起指向它；旧版本的包仍保存在数据库里。
3. 发布前在 staging 用测试账号试一遍：直接选中这个 Skill 发一句话、再用自然说法看能否被自动匹配；涉及真实模型调用时在已批准的测试预算内。
4. 正式环境的发布按 AGENTS.md 第 1 节（上线批准）走。

### 4.3 进行中的对话用哪一版

- **每一轮在准入时冻结当时发布的版本**（`revisionId` 和包哈希一起冻结进执行）。这一轮之后的重放、恢复、续写都用冻结的那一版。
- **下一轮用最新发布的版本**：同一个对话里，发布之后的新一轮自动换到新版本；已经写完的回复不变。
- 定位草稿和选题讨论窗口本来就固定了方法版本（采用时绑定），换平台创作 Skill 不影响它们。

### 4.4 怎么回滚

- 把上一版的 Skill 文件夹原样重新导入并发布（生成一个内容和旧版相同的新版本）。所以**每次发布的原始文件夹要保留**（私有原文目前在
  `~/.graylum/content-skills/`，见 #1021）。
- 紧急停用：在后台把模块设为停用。新一轮立刻不再匹配和选中它；正在进行中的那一轮会因为模块不可用而结束，不再发新调用。
- 回滚和停用都不需要改代码或数据库。

### 4.5 什么时候需要改代码（不属于"只换内容"）

- 新增一种衍生内容来源（`contentSource` 新值）、新的成果类型、新的保存去处；
- 让平台创作 Skill 读新的上下文（例如别的选题、别的会话）；
- 改匹配规则本身（候选过滤、一轮几个 Skill）。

这些按普通任务走 PR、审查和验证。
