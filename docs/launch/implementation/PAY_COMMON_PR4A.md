# PAY-COMMON PR-4A：资格与手续费计算

风险 high；按 #703 拆分方案及其审计结论实现，当前为独立服务合同切片，等待完整审查及主窗口审计。

## 范围

纯资格判定、6% 整数金额计算和只读证据装配，放在现有 payments 服务目录。
不新增退款路由、现金调用、审批写入、数据库迁移或 UI；不改余额与会员。
退款执行及执行前原子复核归 4B；工单界面归 4C。

依据：[方案审计](https://github.com/Crnobog9527/GraylumAI_vercel/pull/703#issuecomment-6021487278)。

- 权威付款时间至可验证的工单提交时间不超过 UTC 168 小时，等于仍可退。
- 任意来源消费过积分即拒绝普通退款；在途或未知结算不能当零消费。
- 法律允许时固定 6%，币种最小单位向下取整；已核实禁止收费则费用为 0，未知适用性待核对；净额不超过原实收减成功退款。
- 会员重购须看完整既往付款历史，旧会员结束、换套餐或改月年周期均不重新获得首购资格；历史缺失待核对。续费不退；拒付、重复退款不再次报价执行；不按现价。
- 例外不套普通的时限/无消费规则；没有合同金额依据则明确待人工核对。
- 先前部分退款不自动排除后续应退例外余款；合同证据必须已扣除/考虑精确的既退金额，净额仍受剩余实收限制。
  部分退款后的普通申请先核对；全额已退、拒付、未决退款不报价。4B 必须验证独立退款意图及去重，不能用余款上限代替防重复。

## 实际接线与证据边界

- `refundMoney.ts`：基于同币种最小单位的整数金额，使用 BigInt 中间值；费用固定 6%，
  拒绝超原实收/剩余可退额、非整数及不安全数值；UTC 时间保留微秒，避免截止后一微秒误放行。
- `refundFacts.ts`：对服务端已读取的账本证据作只读装配，识别整账户的历史消费；
  复用 creditLedger 语义优先级，退款回收、管理员调整不是消费；正数返还不抵消曾经消费。来源不完整、未知借记、在途结算不会投影为“未消费”。
- `refundPolicy.ts`：关联订单、工单、账户与证据覆盖时段；普通退款、例外退款分开判定。
  返回资格/拒绝/待核对、金额及后续权益处理类型，始终 `executable: false`。

本片不新增数据读取接口。只读装配函数接收服务端事实，不自行访问数据库或 Stripe；
这些内部函数也不接收路由/客户端传来的“已验证”布尔值。4B 必须实现并验证真实读取：
完整账户历史（不可 latest-N 截断、不可仅看本单来源）、付款前开启而仍未结算的预留、
原交易付款/退款/拒付事实、工单与订单归属、原子执行前重查。
会员首购还须提供与本次付款/主体匹配的完整历史证据，包含已结束、已退款及其他套餐/周期的既往已付会员；
不能只查询当前有效订阅。付款先后无法确定或历史分页不完整时标为不完整，不能默认首购。上述调用方验证在本片未运行。
缺失/读取失败应传入未知/不完整或停止，不能用空数组和“clear”兜底。

4A 不计算无依据的例外折现，只有服务端已核对、原因/订单/币种匹配的合同金额才可预览；
这不是对任何例外现金执行的批准。未知结算即使已有确定消费也保留，例外仍待核对。
月付/年付/创始会员共用首购资格，具体回收数量、原 Pro 期限、停发/提醒归 4B/4C。
Waffo 仅可描述公共资格合同，不提供渠道执行。违规封闭标志拒绝退款不等于证明了同身份换号拦截。
