## 先说结论（给 Owner 的大白话）

- **默认还是浏览器识别**，不花钱、图片不离开用户电脑。服务器识别只是“后备”。
- **什么时候用服务器**：浏览器某一页没读出来、浏览器太慢（单页超过 20 秒）、或者用户自己想用 AI 识别时，
  页面提示“可以改用 AI 识别，按页扣积分”。**用户点一次确认，这份文档剩下的页才改用 AI**；不点就一直是浏览器识别、不扣钱。
  （推荐这样做，而不是自动扣钱，原因见第 1 节；要 Owner 定，见第 7 节第 1 项。）
- **用哪个模型**：后台单独设置“资料库文字识别模型”。候选是 Claude Haiku 5.5、GPT-6 Luna、Qwen3-VL，
  用不超过 1 美元的 staging 实测比准确率后再定。Gemini 暂不能选（它的图片计价会让冻结金额虚高好几倍，0286 已写明）。
- **扣多少**：按现有公式按实际花费扣。每页模型成本大约 0.001 美元，换算后**每页约 1 积分**（不足 1 积分按 1 积分算）；
  识别前每页先冻结约 3 积分，识别完多退少补。50 页的文件大约 50 积分。页面上不显示预计扣费数字。
- **隐私要改的话**：现在上传区域那句“在你自己的浏览器里自动识别文字，不扣积分”仍然对默认情况成立，但要补一句说明
  “选 AI 识别时，页面图片会发给 AI 模型服务商”。新文案要 Owner 定（第 3 节、第 7 节第 3 项）。隐私条款正文由 Owner 用第三方软件生成，不在本方案。
- **出问题怎么办**：余额不够就暂停、充值后打开资料库自动接着识别；系统原因扣了钱没拿到文字，自动退回一次；
  用户自己中途删文件，照常扣（Owner 2026-10-10 已定的规则）。
- **工作量**：2 个实现 PR（后端 high、前端），加 1 次付费实测；**需要 1 个迁移号**，开工时找总控要。

## 1. 什么时候走服务器

**默认：浏览器识别，不变。** 上传后自动识别、不扣积分，和现在一样。

**出现以下情况时，页面在这份文档旁边提示可以改用 AI 识别：**

1. **浏览器没读出来**：某个单元被标为 `failed`（画不出图、超时、没有文字）。
2. **浏览器太慢**：本机第一页识别超过 20 秒（第 4.5 节的门槛），或者识别引擎在这台设备上起不来（内存不够、不支持 WebAssembly）。
   手机和平板不单独判断，慢了就走这一条（用户基本只用电脑网页）。
3. **用户自己选**：文档菜单里有“用 AI 识别剩下的页”。

**确认一次，整份文档生效。** 用户点确认后，这份文档里**还没完成**的单元（`pending`、`paused`、`failed`）改用 AI 一页一页识别；
关掉页面、充值后再打开资料库，只要这份文档确认过，就自动接着用 AI 识别，不再问。用户可以随时“改回浏览器识别”，正在识别的那一页照常完成和扣费。

**为什么推荐“确认一次”而不是自动扣钱**：

- 上传区域现在写着“在你自己的浏览器里自动识别文字，不扣积分”（Owner 10-17 定的）。不经用户同意就把图片发出去、扣积分，和这句话矛盾。
- 图片会发给模型服务商，属于数据离开 Graylum 的一步，需要用户知情。
- 拒付防护（chargeback）要求扣费有用户主动操作的记录；确认这一下就是记录，存时间和文档 ID，不存别的。

**第一版不做**：已经由浏览器识别完成（`complete`）的页用 AI 重新识别。那要替换已保存的分段、改内容版本，范围更大；
真有需要（比如浏览器识别出来错字多）再单独提。

## 2. 模型、成本和积分

### 2.1 模型怎么选

- 后台新增“资料库文字识别模型”一项，单独配置、不写死、不跟对话模型走（和“报告模型单独设置”同一个做法）。
  只能选：已启用、报价齐全、在路线报价里声明了 `imageInput` 的模型。没配置或不合格时明确拒绝，不偷偷换模型（必测项 23）。
- 候选（OpenRouter 公开模型目录 2026-10-18 的标价，每百万 token 输入/输出美元）：

| 候选 | 输入 | 输出 | 图片单价 | 说明 |
| --- | --- | --- | --- | --- |
| `anthropic/claude-haiku-5.5` | 0.10 | 0.50 | 无（图片按输入 token 计） | 上线主力之一的厂商，推荐首选候选 |
| `openai/gpt-6-luna` | 0.10 | 0.50 | 无 | 已用作整理模型 |
| `qwen/qwen3-vl-30b-a3b-instruct` | 0.15 | 0.60 | 无 | 中文识别通常强，作为对照 |
| Gemini 系列（如 `google/gemini-3.8-flash`） | 0.825 | 4.125 | 有（按 token） | **暂不能选**：0286 的冻结上限是“输入价 + 图片价”都按图片 token 上限算，Gemini 会被重复计一遍，冻结金额约 34 积分/页，实际只用 6 积分左右；要先实测确认计价方式（0286 文档已写） |

- 定哪个：用 LIB-2d 已有的 50 页固定样本（`docs/launch/evidence/LIB-2D-OCR-EVAL-*.md` 用的那套，中文为主、清晰印刷、手机拍照、表格），
  在 staging 跑 3 个候选，比字符准确率和单页实际费用。门槛：准确率不低于浏览器 PaddleOCR 在同一套样本上的结果，单页 ≤ 60 秒。
  两个都达标选便宜的。预计合计不超过 1 美元（第 7 节第 4 项）。

### 2.2 每页成本和积分（按现有公式）

现有公式：**积分 = ceil(成本美元 × credits_per_usd × 倍率)**，staging 现在是 `billing_credits_per_usd = 100`、`billing_token_price_multiplier = 6`，即每 1 美元成本扣 600 积分；每次调用单独进位。

以 Claude Haiku 5.5 / GPT-6 Luna 的标价、一页 1,600×1,131 像素为例：

| | token | 成本 | 积分 |
| --- | --- | --- | --- |
| 实际（估算）：图片约 2,400 + 提示约 600 输入，输出约 1,500（一页中文约 1,500 字） | 3,000 / 1,500 | 约 0.00105 美元 | ceil(0.63) = **1 积分** |
| 冻结上限：图片 token 上限 20,678（0286 公式）+ 文字和模板约 3,000 输入，输出上限 4,096 | 23,678 / 4,096 | 约 0.0044 美元 | ceil(2.65) = **3 积分** |

Qwen3-VL 约为“实际 1 积分、冻结 4 积分”。所以按这几个模型，**每页基本就是 1 积分**，50 页约 50 积分（用户付的钱约 0.5 美元，模型成本约 0.05 美元）。
实际 token 以实测为准，结算按 OpenRouter 返回的官方用量。

### 2.3 冻结和结算（复用 #1042 / 0286，不另建计费）

- **每页一次 BILL2 运行单、一次调用**，计费范围 `{kind:'library_document', documentId}`，用途 `library_ocr`。
  运行单 ID 写进识别单元的 `bill2_request_id`，用来防重复和对账。
- 调用报价用现有的 `runtimePaygCall(request, 'library_ocr', policy, rules, epoch)`：请求是一个 user 消息，内容为“识别提示文字 + 一张内嵌 JPEG”，
  0286 自动算出 T（输入上限）和 U（金额上限）并冻结 `ceil(U × 100 × 6)` 积分。余额不够就不发起。
- 输出上限 4,096 tokens；发给 OpenRouter 的 `provider.max_price` 照 0286 带上。
- 结束后按官方用量结算，多退少补，不超过冻结上限；实际超过 T 时照旧标 `budget_conflict` 并停这条线路（0286 已有规则）。
- 新增的只有：这条路线的 PAYG 主机报价（`runtime/paygHostPolicy.ts` 里加 `library_ocr` 用途和请求格式）、后台模型设置项。

**如果 Owner 想要“每页固定积分”**（不按实际花费）：可以照报告固定价（0295）的做法，但要多一个迁移，而且和 2026-10-10 “按实际花费扣积分”的决定不同。不推荐，见第 7 节第 2 项。

## 4. 流程和各种异常

### 4.1 一页怎么走

不新建队列、调度器或后台服务：**和浏览器识别一样，只在用户开着资料库页面时由浏览器一页一页推进**（第 4.4 节原设计）。

1. 浏览器在识别沙箱里把这一页画成 JPEG（长边 ≤ 1,600 像素、≤ 600,000 字节；Word 图片同样缩放并重新编码），交回页面。
   沙箱仍然断网，图片由页面发给服务器。
2. 页面调 `library.recognizeWithAi({documentId, kind, position, version, image})`，一次一页。
3. 服务端：查开关和这份文档是否确认过 AI → 核对 JPEG 文件头和大小（不解码）→ 限流 → 在账号锁和文档锁下把单元从
   `pending/paused/failed` 改为 `running` 并写入新的运行单 ID（同一单元已经 `running`/`settling`/`complete` 就直接返回现状，不发第二次）→
   按输出上限先占空间 → BILL2 冻结 → 调模型。
4. 拿到文字：按 0287 的规则切段、保存、内容版本加一，单元 `complete`，BILL2 结算。没有文字：单元 `failed`，照常结算（模型确实做了工作）。

### 4.2 Vercel 运行时间

- 一次请求只识别一页、只有一次模型调用，通常 5–20 秒。tRPC 路由 `maxDuration = 300` 秒，单次模型调用超时设 90 秒，留足收尾时间。
- 请求体最大约 0.8 MB（data URL 上限 819,223 字节），在 Vercel 4.5 MB 请求体上限以内。
- 不需要在服务器上分批，“分批”就是浏览器一页一页发；同一用户同时最多 1 页在 AI 识别（一个标签页一次 + 单元锁），不会把函数并发打满。

### 4.3 失败和重试

| 情况 | 单元状态 | 扣费 | 之后 |
| --- | --- | --- | --- |
| 发起前失败（校验、限流、冻结失败、路线不可用） | 回到原状态 | 不扣，冻结立即释放 | 浏览器稍后重试这一页，最多 2 次，然后标 `failed` |
| 已发出、模型报错（402 额度不足、路线拒绝等） | `failed` | 按 BILL2 现有规则（402 不计费，#627） | 用户可以再点 AI 识别 |
| 已发出、请求超时或函数被杀，结果不知道 | `settling` | 冻结保留 | 恢复批次按运行单 ID 查官方费用并结算；文字拿不回来，属于**系统原因**，按第 4.5 节退回一次，单元回到 `pending` 等下次识别 |
| 模型返回空文字 | `failed` | 照常结算 | 提示“这一页没有识别出文字” |
| 文字太长、超出单个文档分段上限 | `failed` | 照常结算 | 和浏览器识别同一个规则（`LIBRARY_TEXT_LIMIT`） |

服务器**不自动重发**已经发出的调用（结果不明确时不能盲目重试）。

### 4.4 余额不足

冻结失败（余额不够这一页的上限）时不发起，单元标 `paused`，这份文档的 AI 识别停在这一页之前，已识别的页保留，余额永远不为负。
页面显示「余额不足，已暂停识别；充值后打开资料库会自动继续」。充值后再打开资料库，浏览器自动从暂停的那页接着识别（只限确认过 AI 的文档）。

空间不够时同样不发起，单元 `paused`，提示腾出空间（和浏览器识别现在的规则一样）。

### 4.5 中途删除、注销、退款

- **用户删除文档**：删除先拿文档锁，之后同一文档的新调用被计费范围拒绝（0286）。已发出的那一页结果丢弃、不保存，
  **照常按实际费用扣、不退**（Owner 2026-10-10 决定）。识别单元随文档级联删除，对账从 BILL2 那边按用途 `library_ocr` 找运行单，
  不依赖单元行还在。
- **账号注销**：注销开始后不再发起；已发出的结果丢弃、**退回积分**（系统原因，Owner 2026-10-10）。计费记录里本来就没有图片和文字（0286）。
- **系统原因退回**（进程崩溃、超时拿不到文字、注销清理）：按运行单 ID 只退一次。实现上包一层现有的 `bill2_payg_compensate`，
  加一个“这个运行单已退过”的判断，不另写退款逻辑。
- **恢复批次**：接进每日对账 cron（上线升级 Vercel Pro 后改为每小时），另外用户打开资料库时也对本人的未结运行单跑一次，
  页面不会一直停在“识别中”。限时运行，没跑完的留到下次；仍查不到费用的交给现有“卡住调用”流程由管理员处理。
- **会员退款**（整单退款）：识别扣的积分和对话一样从积分账户扣，按现有退款规则处理，这里不加特殊规则。

## 6. 不做什么

- 不在服务器上打开 PDF 或 Word（安全规则不变）：页面图片仍由浏览器画出来。
- 不用 OpenRouter 的整份 PDF 文件解析（`file-parser` / `mistral-ocr`）：它的解析费会不会出现在用量里没有核实，没法冻结和结算（`lib-2d` 开工前核对第 5 项）。
- 不建服务器队列、定时识别、后台常驻任务；用户不开页面就不识别（第 4.4 节原设计）。
- 不让 Agent 看图片；不识别资料库里单独上传的图片文件。

## 7. 需要 Owner 定的事

1. **什么时候走服务器**（推荐 A）
   - A：默认浏览器；读不出来或太慢时提示，用户每份文档点一次确认才改用 AI 扣积分。可以直接复制：
     「同意：扫描件默认用浏览器识别；浏览器读不出来或太慢时提示，用户确认后这份文档剩下的页改用 AI 识别、按页扣积分。」
   - B：浏览器读不出来时自动改用 AI，不问用户（和现在上传区域那句“不扣积分”冲突，要一起改文案）。
2. **怎么收费**（推荐 A）
   - A：按实际花费（现有公式，每页约 1 积分）。可以直接复制：「同意：AI 识别按实际花费扣积分，用现有计费公式。」
   - B：每页固定积分（多一个迁移，和 10-10 的决定不同）。
3. **新增的用户可见文字**：上传区域补的那句、确认框那段（第 3 节表格里的草稿）。可以直接复制：
   「同意第 3 节的上传区域补充句和确认框文字。」或者直接改字后回复。
4. **付费实测**：staging 上 3 个候选模型、50 页样本，预计不超过 1 美元，从 OpenRouter 现有余额出（10-02 已授权测试可自主使用现有余额，这里报备）。

其他都是技术选择，由 AI 决定：单页图片尺寸、输出上限、超时时间、重试次数、恢复批次频率、模型准确率门槛。
