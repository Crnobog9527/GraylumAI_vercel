# provider_rejected 会话视图持久提示

风险：high（数据库迁移、账单事实的只读投影）。范围：后端迁移与本机测试。
来源：PR #627 评论 5982259111；起点 staging ad02ab4e。

## 实现约定

- 从 `bill2_calls.provider_rejected` 推导 `runtime_view.executions[].unavailableReason`。
- 只有已结束、账单无冲突、最终扣分为零且具有明确拒绝事实的轮次才返回
  `provider_rejected`；不把普通取消、门控取消、正常完成或未知费用标成拒绝。
- 保留原有 unavailable reason 的优先级、内容权限与账单投影。
- 不新增表、不回填旧数据、不在宿主重复保存原因、不改前端。
- 最新 `runtime_view(uuid,uuid)` 来自 0166；0107、0124、0163 是被替换的历史定义。
  0164、0165、0167 不替换该视图。
- 本任务使用 0169，#633 使用 0168；共同修改 built-fingerprint.json。
  后合并者按实际顺序调整迁移编号并重新生成指纹，不能手工合并散列。

## 兼容性与交付边界

新增的是现有可空字符串字段的一个值，旧客户端仍接受该响应。
这是 `unavailableReason: string | null` 的新增取值，不是新增必填字段。
现有显式原因（例如 `provider_history`、`latest_unavailable`）继续优先；
原有 `output_truncated` 分支保留；不符合推导条件时仍走原逻辑，通常为 null。

旧客户端未识别 `provider_rejected`，不会因为这个值报错或显示原始错误：

- 工作对话 `/runtime`：取消轮次继续显示“这一轮没有完成，已结束。原记录已保留，
  不会自动重试；可以重新发送。”（若本地仍有门控/主动停止状态，则沿用该状态提示）。
- 导师对话/选题页：没有可用正文或卡片时继续显示“本次执行已停止，未取得可用回复。
  原记录已保留；请查看错误提示或继续讨论，系统不会自动重放这条请求。”
  已有正文/卡片按原逻辑保留。
- “服务暂时不可用，没有扣积分。”的专用持久文案由后续前端 PR 接入；本 PR 不宣称已显示。

推导只读；历史 v1/v2 轮次不需要回填。无已派发调用、门控拦截、普通取消、正常完成、
非零扣分、未知费用或冲突账单均不新增该原因。一个轮次中如果先有非拒绝调用
（即使最终费用为零），也不笼统标记为生成前拒绝。
会话入口、actor/scope 检查、可见内容检查及 service-only RPC 权限保持原样。

0169 使用 0166 源定义 MD5 和完整目标 MD5 双向核对；精确目标可重复执行，其他漂移拒绝。
事务失败恢复原定义/ACL。代码回退到旧客户端兼容；如需撤销数据库显示变化，
后续授权迁移恢复 0166 的原函数定义即可，不需要删除或改写账单数据。
仅 draft 交付；不访问远端数据库，不应用迁移，不改配置，不做付费调用，
不转 ready，不触发审查机器人，不合并。独立审查在实现交接后进行。
