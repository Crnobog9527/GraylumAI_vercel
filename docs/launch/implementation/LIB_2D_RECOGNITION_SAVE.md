# LIB-2d：服务端保存浏览器识别出的文字（迁移 0287）

风险 high（数据库、资料库额度）。依据 Owner 2026-10-17「扫描件 PDF 和 Word 里的扫描图片用浏览器识别（PaddleOCR）」；
识别在用户浏览器里完成（#1046、#1048），服务端**只收文字**，不收图片、不调模型、不扣积分。
后台开关 `system_settings.library_scan_recognition_enabled` 默认没有（关闭）；关闭时所有保存被拒，待识别列表为空。

## 做了什么

- **Word 上传时建图片识别单元**：`completeWordUpload` 可以带上浏览器提取到的图片位置（LIB-2b 的 `DocxImage.offset`），
  服务端把每个位置换算成「前面有几个提取段」（anchor），新的 `library_word_publish(…, images)` 为每张图建一行
  `word_image` 识别单元，前 50 张待识别，其余标为超出上限（和 PDF 扫描页同一个上限）。不带图片位置时行为和以前完全一样。
- **待识别列表** `recognitionPending`：本人最早的 20 份还有待识别（或暂停）单元的 PDF / Word 文档，每份最多 50 个位置。
- **保存一页 / 一张图的文字** `saveRecognizedPage`：服务端按现有规则切段（每段 ≤ 8,192 字节），在账号锁和文档锁下：
  - 只认本人、可用、未删除的文档，PDF 页只能存进 PDF、Word 图只能存进 Word；
  - 一个单元只保存一次：刷新、重试或两个标签页同时保存，第二次什么都不改；
  - 内容版本要对得上（否则提示重新读取），保存后内容版本加一，旧版本的读取被拒（LIB-4 的规则不变）；
  - 文字插在正确的位置：PDF 页排在前面各页之后，Word 图片排在它后面那个提取段之前；分段序号始终连续；
  - 识别出的文字计入空间；空间不够时这一个单元标为「暂停」、什么都不存，腾出空间后再保存即可。
- **标为失败** `failRecognizedPage`：浏览器读不出的单元（画不出的图片、超时、没有文字）标为 `failed`，什么都不存。

迁移 0287 只追加：识别单元多一个 `failed` 状态和 Word 图片的 `anchor` 列（只在 `word_image` 行上有值），
新函数和 `library_word_publish` 的六参数重载；旧的五参数发布函数不变。注销和单条删除沿用现有的级联删除（分段、识别单元）。

## 验证

- SQL（`packages/db/tests/library/recognition.mjs`，随 `run-local.mjs` 运行）：开关、他人/类型/版本/页码拒绝、坏分段拒绝且不改数据、
  已完成页不被覆盖、PDF 页和 Word 图的插入顺序与连续序号、空间计入、旧版本读取被拒、重复保存不改、
  两个连接并发保存同一页只成功一次、空间不够暂停且不存、失败标记、删除后拒绝、anon / authenticated 无权限。
  去掉 0287 时同一组用例失败（先红后绿）；0287 在历史位置连续执行两次结构不变；`built-fingerprint.json` 已更新。
- API 单元测试：`recognition.test.ts`（输入范围、切段、拒绝控制字符、RPC 参数、限流、Word anchor 换算）。
