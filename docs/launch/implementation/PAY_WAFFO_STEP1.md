# PAY-WAFFO 第 1 步：统一资格、路由与原来源

依据：[已批准方案](../tasks/PAY-WAFFO.md) 第 8 节第 1 步；风险 high。
本步骤为分阶段、默认关闭的基础契约，不能据此启售。无供应商调用、远端数据或配置变更。

## 已实现

- `payment_method_routes` 的三种方式独立开关和版本检查；银行卡固定 Waffo 订阅，钱包固定 Stripe 单笔。
  缺配置拒绝新协议购买，live 新购硬拒绝。钱包年期另查该方式的验证标记。
  新协议配置存在后，旧建单入口不能创建新订单；原意图保留原来源。
- 复用 payment_orders：付款方式、续费事实、月/年/30 天期限、条款版本和同意时间、资格预留。
  同账号未决意图禁止切方式；原意图在设置改变后仍按原身份处理。
- 服务端资格：Gold 首 30 天 4900 美分、创始年期 49600 美分；Gold 历史跨方式、含退款。
  按身份摘要串行首购，按 test/live 分池原子预留创始 50 个历史名额。
  只有可信供应商适配器确认会话关闭且未付才释放；释放后迟到实付进 review，不开权限。
  升级与创始续买的收款状态转换留 PR-2，普通购买入口拒绝绕过转换重复买会员。
- Gold 识别复用 0151 的 HMAC 原料，派生独立用途摘要；不存邮箱、IP、设备或新密钥。
  独立用途与 test/live 隔离，保留至最后 Gold 交易年度结束后一年；原注销事务同步保存，现有注销 cron 清过期。
- provider refs 唯一身份包含模式；标准价/首期/创始变体共用原映射表。Waffo 最小收件表只记商户、模式、
  事件类型/ID、权威查单所需对象引用、正文摘要及处理状态，不存原文/联系信息；验签、查单及收件后的处理留 PR-2。
  现有套餐管理只读写 standard 映射；保存/清空标准价格不会停用或收编优惠变体。
  Stripe 结账记录与包发放同样限定商户/模式；旧两参数调用仅在编号唯一时继续，歧义拒绝，不猜原来源。
  旧年期积分查询按订阅商户/模式，退款回收传入服务端原订单 ID，由事务锁定内部订阅及 grant。
  退款预览同样必须显式传入商户/模式，避免同编号的另一来源进入预览。
  原退款算法仅增加来源定位：保留 profile → subscription → grant 锁序、首事件终止、余额封顶和幂等。
  新发放按原订单隔离账本键、按内部订阅隔离周期；新来源退款按内部订阅隔离幂等键。
  历史 grant 保留旧退款键/旧 RPC 签名；旧无范围退款调用遇同账号同编号多个订阅时在 profile 锁内拒绝。
  补 bigint 账本返回旧 integer 契约的重放转换。
- 内部订阅与发放不需要伪造 Stripe ID；BILL2 原预扣、结算、释放使用内部来源，保留退款待核对隔离。
  年期快照保存全年积分总数，仍由原 12 期算法分配。

旧失败且未付款的历史订单不再阻塞新意图；已付未履约仍阻塞，避免重复收费。

退款新增两个限定来源的 RPC 是原事务算法的适配：旧签名只有外部编号，无法定位第二个商户/模式的内部订阅。
从已存在函数定义生成、以真实 SQL 验证全部锁定查询，复用原订单、订阅、grant 和账本，不建立第二套回收账。
应用须在 0204 后部署；回退应用仅支持历史 Stripe 标识，不能开启新内部来源的收款。

只增加 Waffo 收件表：原 provider refs 表示对象归属，不能表示收到但尚未履约的事件；
收件表不承担现金或权益权威。不另建账本、会员系统、队列或调度。

  回退应用不撤销迁移、不恢复新销售；不能把代码回退当作财务数据恢复。
