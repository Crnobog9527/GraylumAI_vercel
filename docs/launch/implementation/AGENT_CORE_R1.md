# AGENT-CORE R1 — 已发布 Skill 文件读取

风险：high（导师工具权限、持久化与调用预算）。按 #771 派发，本窗口负责 R1 → R16 后端 → R4；不合并。

导师现在可在一次非开场回合内调用一次 `read_skill_file({path})`，然后继续回答或给出提问卡。
文件必须属于本次执行绑定的已发布 Skill 版本，使用精确相对路径；不允许指定其他 Skill、版本或任意地址。
每文件最多 16,000 UTF-8 字节，不静默截断。开场回合和旧冻结请求保持原工具列表。

## 实现与边界

- 复用 loader 的声明路径、版本、SHA-256、发布/撤销检查，以及现有 `runtime_tool_calls` 冻结结果。
- 总控为本 PR 分配 0205，扩展现有 `runtime_tool` RPC，不增加表。SQL 独立校验归属、路径、文件大小和保存结果。
- 首次使用数据库保存后的 JSON；恢复使用相同保存结果，仍复核发布权限。SDK 后续请求由现有 BILL2 收据重放，不重复派发。
- 导师最多两次模型调用，读取工具最多一次；附带整理另占一次。每次请求仍按现有预算、容量和停止条件检查。
- 准入先通过既有 loader 校验并测量可读文件的编码大小，冻结续答容量预留；历史块选取保留这部分空间。
  复用现有资源缓存，不新增缓存。测量首尾复查权限，实际文件读取仍逐次由数据库校验；暖缓存只新增 2 次权限 RPC。首次冷读取会增加准备耗时，后续 R7 实测应覆盖它。容量不足在付费调用前拒绝。
- 首次读文件响应最多 8 KiB 编码轨迹；超限、续答再次读文件、确定性文件拒绝与参数错误（含 NUL、孤立代理项、不合法调用标识）走现有取消结算，恢复不重复派发；临时数据库故障保留恢复能力。
- `runtime_request_timing` 对读文件回合添加 `skillFileRead` 和 `afterSkillFileMarks`；首字毫秒值仍从请求开始计时。
  不记录文件路径或内容。
- 将原 `read_source`/search 构造代码原样拆到 `sourceRuntimeTool.ts`，保持 execute.ts 的大小限制；没有扩展资料库读取。
- 不新增前端入口、公开 HTTP API 或环境设置；不改 R5 的 runtime 路由或 #778 的 root.ts。

内部工具拒绝包括 `RUNTIME_SKILL_FILE_DENIED`、`RUNTIME_SKILL_FILE_TOO_LARGE`、
`RUNTIME_SKILL_FILE_CONFLICT`；RPC 失败仍通过现有安全错误包装，不对客户端泄露数据库或 Skill 内容。
撤销、删除、取消等既有服务端限制继续生效，不允许以缓存或重放绕过。

## 发布和恢复

迁移 0205 必须排在 #778 的 0203、#781 的 0204 之后。合并和应用前置迁移后再同步重建正式文件库指纹。
本地数据库测试只证明当前文件集合及 0205 行为，不代替包含前置迁移的最终指纹和 CI。
迁移对旧 search/read_source 分支保持兼容，可重复执行；新记录继续受已有单条删除和注销覆盖。
代码回退时不得让旧执行器接手含 skillFile 的新冻结请求：先停止新请求并排空运行中请求，或恢复本版本继续处理。
不删除已保存工具结果或账务证据。
