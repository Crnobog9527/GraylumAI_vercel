# AGENT-CORE R8b：其他带步骤 Skill 接入导师流程（范围和方案）

风险：high（启动和发布函数、计费范围、正式版本指向）。依据 `AGENT_CORE_CLOSEOUT.md` R8b、Master Plan 第 3.4 节、
`CONTENT_CONVERSATION_DRIVEN_PLAN.md`（#621）第 3.1、9.1、9.3 节；总控-7 派发。

## 要做到什么

任意带步骤的 Skill（例如写口播稿）和定位用同一套体验：导师先开口、提问卡、每轮回复后自动整理进右侧面板、
每步确认卡、回头修改后复核。页面和数据库**不写死某个 Skill**：步骤、字段、整理模板都来自 Skill 自己的
`workflow.yaml`（R3 已支持 `organizerTemplate`）。

## 现在卡在哪里（已核对 staging）

| 位置 | 现状 | 对非定位 Skill 的影响 |
| --- | --- | --- |
| `opc_information_schema`（0107） | 要求整个流程有 1–24 个 `profileKey` 字段 | 没有 profileKey 的 Skill 启动直接失败 |
| `opcService.catalog` + `/positioning` 起始页 | 只列定位流程，并固定取第一个 | 选不了别的 Skill |
| `opc_start` / `opc_start_b1` | 成果类型写死 `positioning`，总会建"业务"并绑定 | 发布后会把这个 Skill 的结果当成用户的"当前定位"，影响自由对话、定位前置检查和选题 |
| `runtime.choices` / 技能广场 | 带步骤的 Skill 也会出现在旧 `/runtime` 列表里，当作没有步骤的普通 Skill 跑 | 没有右侧面板、没有提问卡和确认卡 |
| 页面文案和后续动作 | 右侧清单叫"定位清单"、定位总结、选题承接、"我已有定位" | 名字和后续动作对不上 |

整理（`opc_capture_apply`）、确认（`useStepConfirmation`）、提问卡、确认卡、R3 整理模板本身已经是通用的。

## 怎么做（拆成三个 PR，按顺序）

**PR-1 后端（迁移 1 个，编号向总控要）**

- 区分两类流程：有 `profileKey` 的是定位流程（规则不变）；没有 `profileKey`、但每步都有字段的是"带步骤 Skill"。
  `opc_information_schema` 只对定位流程要求 profileKey，其余检查（每步 1–24 个字段、字段 id 格式）照旧。
- 启动：`opc.start` 接受指定的 Skill 注册编号。带步骤 Skill 的成果类型用新的 `step_skill`，**不建业务、不绑定业务**，
  所以发布后不会成为"当前定位"，不进自由对话的定位来源、不触发选题。
- 新接口 `opc.stepCatalog`：列出用户能用的带步骤 Skill（沿用现有 Skill 可见性和会员规则）。
- `runtime.choices` 排除带步骤 Skill（定位和其他带步骤 Skill），用新的数据库函数 `opc_step_flow_modules` 判断，
  不读 Skill 包、不受目录 100 条上限影响。意图匹配（自动选 Skill）的排除随 #621 第 3.1 节做，本 PR 不改准入热路径。
- 定位来源只认定位版本：`opc_source_allowed` 对带步骤 Skill 的版本返回否，所以它不会被选题、计划、账号策略、
  自由对话当作定位读取。
- 草稿列表接口带上流程类型，前端据此区分。
- 测试：仓库里放一个固定的 3 步"口播稿"样本 Skill（只用于测试，不发布到 staging），本地数据库测试覆盖启动、
  整理写入字段、确认、发布不改当前定位、定位流程行为不变；API 单测覆盖目录和过滤。

**PR-2 前端**

- 新路由 `/skills/[draftId]`（带步骤 Skill 的工作区），复用定位工作区的组件：对话、提问卡、右侧整理面板、确认卡、
  报告面板（Skill 声明了报告时才显示）。不带定位专属部分：定位总结、选题承接、"我已有定位"、计划和交接。
- 右侧面板标题和清单名从"定位清单"改成用 Skill 名称（定位页面仍显示"定位清单"）。
- 技能广场里带步骤的 Skill，"开始"按钮走新的启动，进入 `/skills/[draftId]`；侧栏草稿列表按类型分开。
- 不碰输入框组件（另一个窗口在改）；`runtime/page.tsx` 不动（#621 独占）。工作区外框 `workspace-frame.tsx`
  只加按类型分组，改动尽量小，和 R8a 排队时再合。

**PR-3 staging 验收**

- 在 staging 后台发布一个真实的带步骤测试 Skill（例如 3 步口播稿），用真实模型走一遍：开场、提问卡、整理、
  每步确认、回头修改、刷新恢复；同时确认定位流程不受影响。浏览器验收交 Codex。

## 不做什么

- 不改定位流程的行为和规则；不改自由对话和内容创作（R8a / #621）；不改输入框组件。
- 不做"我已有某某"这类导入入口（定位的 R15 不推广到其他 Skill）。
- 不做旧入口下线（LEGACY-CLOSE）。
