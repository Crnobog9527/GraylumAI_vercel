# DATA-ERASURE：账号注销与数据删除 — 实施说明

> 产品规则以 [Master Plan v12](../MASTER_PLAN.md) 第 5、7、10 节（D7）为准。本任务**设计先行**：在 AGENT-CORE 的 AC-2 新建任何表之前，先写出并审查一页删除规则；实现在公开上线前完成。

## 现状（2026-09-27 核实）

- 代码里没有任何注销或删除账号的功能。
- 成果和定位记录有禁止修改和删除的触发器（迁移 0066、0107）。
- 新 Runtime 和计费的表指向用户资料时没有删除规则（迁移 0105、0106），直接删除用户会被数据库拒绝。
- 隐私条款没有提删除权和第三方模型供应商（`apps/web/src/lib/landing-content.ts`），服务条款页仍是草案。

## 删除规则需要写清的内容

1. **范围清单**：所有保存用户内容的表、存储桶、日志和第三方（模型供应商、支付商、邮件），逐项写明删除、清空正文还是保留，以及理由。
2. **账务**：保留金额、编号、时间；在途或结果未知的运行单保留核对所需的最少信息，核对完成后清除正文。
3. **冷静期**：提交注销后若干天内可以撤销，防止误删和盗号，到期后执行。
4. **防刷**：注销后保留不可逆的账号标识，同一邮箱或同一第三方登录再次注册时不重复发放开户积分。
5. **订阅**：有生效中的订阅或未完成的退款时，先处理订阅再注销。
6. **备份**：说明备份里的数据多久后自然过期。
7. **条款同步**：隐私条款写明删除权、保留期限、第三方模型供应商及其数据政策。
8. **验收**：用测试账号走完"上传文件、生成画像、对话、注销"，逐表检查正文已清除、账务记录仍可对账。

## 对其他任务的要求

从 v12 生效起，任何新增保存用户私有内容的任务（包括 AGENT-CORE 的附属会话、整理笔记和反馈记录，FUSION 的结果，LIB-DOCS 和 VOICE 的数据），新表从建表起就按可删除设计：正文和账务字段分开存放，不加整表禁止删除的触发器，并把"注销后这些内容被清除"列入自己的验收。

## 必测项清单

1. 注销后，各任务新增的私有内容全部清除（逐项列表验证）。
2. 注销后账务仍可对账，金额、编号、时间保留。
3. 结果未知的运行单在核对完成前保留最少信息，完成后清除正文。
4. 同一邮箱重新注册不重复发放开户积分。
5. 冷静期内撤销注销，数据完整。
