  （0204 `pay_waffo_create_purchase`、0211 `pay_waffo_admit_purchase` / `pay_waffo_founder_deadline`），
  由 PAY-STRIPE-MP 窗口沿用和改造，本任务只读不写。不做创始人寄语（仍待定）、不做"功能需求优先开发"（第 51 项写明不承诺）、

## 4. 设计

### 4.1 "现在是不是创始会员"：一个只读函数

新增 SQL 函数 `pay_founder_status(p_user uuid)`（security definer，只读；**撤销 `PUBLIC`、`anon`、`authenticated` 的执行权限，只授予服务端角色**，
前端和普通用户不能直接调用，用户只能通过服务端接口查自己的状态，服务端用登录身份决定 `p_user`），返回 `active` / `grace` / `ended` / `none`
和依据的订单号、当前期末、资格截止时间。规则全部取自已有字段，不加"创始会员"状态列：

- `none`：从没有过 `qualification_state='sold'` 的 `founder` 订单。
- `active`：最近一张已售创始（或 `founder_renewal`）订单的会员期还没结束，且没有退款、没有被拒付冻结。
- `grace`：会员期已过，但还在 `pay_waffo_founder_deadline` 之内（银行卡：续费失败起 7 天；钱包：到期后 7 天内可按创始价续买）。
  宽限期内徽章和展示照常（记录 V"宽限期 7 天"），社群不动。
- `ended`：超过截止时间没续上；或这份创始付款被退款（记录 V"退款立即结束"）；或拒付判输（CHARGEBACK 上线后写入）；
  或功能缩减按剩余时间退款。`ended` 一旦出现就不再回到 `active`（之后再买按当时价格，不恢复创始身份），由函数按历史判断，不靠一个可以被改回去的标志。
- 拒付期间（PAY-DISPUTE-GUARD 冻结中）：推荐按 `ended` 对外处理（徽章和展示先撤下），判赢解冻后自动恢复；这是 Owner 决定项 F5。

两条 Stripe 通道的差别只在"续费事实"从哪里来：MP 和中国大陆银行卡都是 Stripe 订阅、同一个锁价价格自动续费
（#847 已验证第 365 天按 496 续费），续费成功后由 MP 窗口的 Stripe 续费处理写下一期订单；钱包是用户手动再买 `founder_renewal`。
函数只看订单结果，所以三条路共用一套判断。

### 4.2 徽章

- 站内：个人中心、侧栏头像旁显示"创始会员"徽章，`active` / `grace` 显示，其他不显示。徽章是前端按 4.1 的结果渲染，不存图片、不存状态。
- 公开：只出现在展示墙卡片上，跟随展示墙的公开同意。
- 视觉稿：沿用 DESIGN.md 设计变量；具体样式没有定稿，由 PAYWALL 窗口出一版给 Owner 看（决定项 F4）。

### 4.3 展示墙（公开同意）

- 新表 `founder_wall_entries`（一人一行）：`user_id`、展示名、最多 3 个社媒账号卡片（平台 + 账号名 + 主页链接）、可选的产品名和链接、
  一句话介绍（限长）、`consent_version`、`consented_at`、`withdrawn_at`、`review_state`（待审 / 已通过 / 已拒绝）、`reviewed_at`。
  **为什么要新表**（AGENTS 第 5 节）：现有 `data_use_consents`（0212）只允许 `team_improvement` 一种用途、没有放展示内容的地方；
  订单表是账务记录（3 年），不能放会被公开的个人内容。公开同意的时间和版本记在这张表里，撤回时清空展示内容、只留时间和版本，按同意记录保留 1 年后删除。
- 流程：创始会员在个人中心打开"加入创始会员墙"→ 填写卡片 → 勾选"我同意在 Graylum 网站公开展示以上内容"（默认不勾）→ 提交后进入待审 →
  管理员在后台通过后才出现在墙上（推荐先审后发，因为是公开页面，防止垃圾链接；决定项 F3）。随时可以撤回，撤回立即从墙上消失。
- 展示条件：`review_state=已通过`、没有撤回、`pay_founder_status` 为 `active` 或 `grace`。身份变成 `ended` 时自动不显示（不删行，用户可看到"身份已结束，卡片已下架"）。
- 公开页面：`/founders`（具体路径随 PUBLIC-SITE 的 `/app` 搬迁定），只读、服务端渲染、外链加 `rel="nofollow ugc"`；
  人数太少时是否先不开放这个页面，是决定项 F6。
- 注销：`account_erasure_local_cleanup` 增加删除这张表该用户的行（同意时间按 1 年规则另留不含内容的记录）。

### 4.4 会员社群（人工办理）

- 平台由 Owner 定（决定项 F1）。系统只做两件事：
  1. 成为创始会员后，在个人中心显示"加入创始会员社群"的说明和入口（入口链接由管理员在后台 `system_settings` 里填，不写死在代码里）；
  2. 后台"创始会员"页面：列出所有 `active` / `grace` / `ended` 的创始会员（内部编号、加入时间、状态、状态变化时间、管理员手动勾的"已入群""已移出"），
     并单独列出"身份已结束但还没标记移出"的人，方便 Owner 定期清理。
- 社群办理状态要存下来：新表 `founder_community_status`（一个创始会员一行：`user_id`、`joined_at`、`joined_by`、`removed_at`、`removed_by`），
  只有管理员能写，写接口按"已入群 / 已移出"两个动作做，重复点击结果不变。"待移出"= `pay_founder_status` 为 `ended` 且 `joined_at` 有值、`removed_at` 为空，
  由查询算出，不另存。注销时删除该用户的行。不放进 `founder_wall_entries`，因为展示墙只有自愿公开的人才有记录。
- 列表只显示内部编号和登录邮箱（邮箱只在后台、只给管理员看），不导出到第三方。
- 退群流程（设计稿 README 第 73 行"还没有设计"）：推荐身份结束后 7 天内由 Owner 移出，并发一封通知（走 PAY-NOTIFY，决定项 F2）。

## 6. 验收（Stripe 测试模式 + 本机数据库测试）

- **正常**：分别用 MP 测试卡、`card_cn` 测试卡、支付宝测试付款买创始年付 → `pay_founder_status=active`、个人中心有徽章；
  填写展示卡并同意 → 待审 → 后台通过 → 公开墙出现；撤回 → 立即消失。
- **到期和宽限**：测试时钟推到第 365 天续费成功 → 仍 `active`；续费失败（`4000…0341`）→ 7 天内 `grace`、徽章和展示还在 → 第 8 天 `ended`、
  墙上消失、后台"待移出社群"出现这个人；钱包创始到期后第 7 天内续买 → 恢复 `active`，第 8 天以后再买 → 不按创始价（收款核心已拒绝）且仍 `ended`。
- **退款**：7 天内退款（后台审批、模拟 Link 代退各一次）→ 立即 `ended`；之后名额计数不变（不放回）。
- **重复**：同一回调重复投递、同一人重复提交展示卡 → 只有一行、结果一样。
- **并发**：同一用户两个标签页同时提交和撤回 → 最终状态确定且只有一行；身份结束和用户提交卡片同时发生 → 卡片不会出现在墙上。
- **失败**：`ended` 用户、非创始会员、未勾选同意的提交一律拒绝；用普通用户和匿名身份直接调用 `pay_founder_status` 被拒绝，通过接口查别人的状态被拒绝；管理员以外的人读不到后台名单和邮箱；注销后表里没有该用户内容。
- **社群名单**：管理员标记"已入群" → 身份结束后出现在"待移出" → 标记"已移出"后消失；重复标记结果不变；非管理员写入被拒绝。
- Codex 浏览器验收（一次一个任务）：徽章显示、填写/撤回、公开墙、后台审核。
