## 1. 身份与依赖

七阶段的严格先后关系为：

`V3-BILL-2 → V3-RUNTIME → V3-WORKBENCH → V3-OPC-UI → V3-FEISHU → V3-GOLD → V3-LEGACY-CLOSE → V3-M3 → REL-1`。

其余依赖以 plan-core 表为准，尤其保留 `V3-PACKAGE-RESEARCH → V3-ARTIFACTS → V3-WORKBENCH` 和原 BILL-1/PAY-1/CI-1 约束。不能仅沿这一条新链判定就绪。

| 阶段/任务 | 复用与新增范围 | 必须交付的验收 |
| --- | --- | --- |
| 1 `V3-BILL-2` | 新任务；复用 BILL-1 对账及唯一钱路、REFUND-1B 来源保护、旧聊天和 #414 调用身份模式；新增聚合运行单与官方收据接口 | [独立账务契约](V3-BILL-2-provider-authoritative-billing.md)全部本地/隔离验收；两种归属、金额、预算、事务互斥、未知恢复、兼容与回退证据 |
| 2 `V3-RUNTIME` | 新任务；复用已入库 SDK 切片、Skill loader、成果与权限；把第一批接口接入统一执行和 Supabase-backed SDK Session | draft/work item 独立 Session，普通/Skill/整理模型职责不可越权；受控搜索/资料工具、调用上限、刷新/多标签/断线恢复；先验权和持久身份再 dispatch；账务故障场景重验。不能将旧手写上下文或暂存内存称为持久 Session |
| 3 `V3-WORKBENCH` | 复用既有未完成身份，扩展 OPC 首条链路；必要的草稿、确认承接与项目/工作项绑定继续用现有成果机制；旧已交付网页/成果不重建 | 零项目用户、导师六步与手动入口同结构、中途恢复、草稿内生成/编辑/确认周计划、幂等承接到一/多账号、一个选题调用一个 Skill 保存成果并重新登录找回；确认不调用模型/不收费，冲突不覆盖，费用/Session 不复制；同时完成既有通用配置与非工作流 Skill 验收 |
| 4 `V3-OPC-UI` | 新任务；在阶段 3 可用页面上完成全站信息架构与输入框，不重复开发业务流程 | 顶部“首页/项目/技能广场/个人中心”，项目/工作项深链接；Skill 菜单、文件、普通模型与连接器管理；连接器无一级导航。桌面/平板/移动、键盘/焦点、空态/权限/断线恢复通过；阶段 5/6 未就绪能力不伪装可用 |
| 5 `V3-FEISHU` | 新任务；首个真实连接器闭环；复用阶段 2 权限和阶段 4 输入框入口 | OAuth 最小权限、用户明确指定资料读取、多维表格字段映射、确认内容/目标后写入与幂等更新；超时先读回、撤权后拒绝、跨用户/表越权拒绝。真实 OAuth/写入需另行授权；Notion/Slack 仍为产品后续范围，不在本节点自动开工 |
| 6 `V3-GOLD` | 新任务；使用同一账务/Runtime，新增多模型产品与官方总收据适配 | 冻结同一 Skill revision/输入/成果版本，各原稿和综合稿可追溯，参与/分析失败如实展示，外部写动作不随模型扇出；Gold 服务端准入、模型配置与预算；独立授权低额度真实对账通过后才开放生产计费 |
| 7 `V3-LEGACY-CLOSE` | 新任务；只收口已被验证覆盖的旧路径，前向迁移，不删除历史 SQL | 用调用方/路由清单及新路径证据证明可删，再移除旧模型路由、正则联网、手写上下文、重复执行器/页面与会员历史清理配置/API/cron；深链接/旧结果/未决费用可恢复，用户和法律删除保留；全量相关回归与 Owner 体验验收 |

每阶段均需对应精确候选的 CI/Security、独立 Codex 语义审查、适用的真实本地/非生产验证及 Owner 产品验收。阶段 1 没有新页面，Owner 审阅账务行为即可；阶段 2 以后按实际 UI 变化提供可访问体验入口。各阶段具体外部授权不互相继承。
