## 预留与停止条件

沿用 #582 口径：`T = 完整最终请求 UTF-8 字节数 B + 4096 协议开销 + 4096 安全余量`。
导师每次预留 `(T × 2.5 + 8192 × 10) / 1,000,000`；整理每次预留 `(T × 0.25 + 2048 × 0.75) / 1,000,000`。
复用既有 `openRouterCallBound` 向上取整，再向上取整到纳美元记账。该口径不是模型 tokenizer 实测。

绝对输入上限对应的单次预留为导师 **$0.327400**、整理 **$0.019584**；
100 次全按输入上限计算为 **$23.505520**，不能保证 $9 内跑完全部样本，也不申请扩大预算。
完整 provider context 的宿主报价 $2.58192/$0.264036 仍保留在本机准入夹具中，
与评测出口按实际 wire 的逐次预留不同，不修改生产报价逻辑。

严格串行，发送前先把次数和预留写入本机账本。只有官方响应提供明确费用且不高于该次预留，才结算并释放差额。
下一次发送必须满足“已结算费用 + 未结算预留 + 本次预留 ≤ $9”。失败也占次数；最多 70 导师、30 整理。
无授权、摘要变化、到期、认证/代理/网络错误、非成功响应、截断、坏流、费用未知/超预留、
持久化失败、次数/预算不足或本机 Runtime/捕获失败均立即停止。不重试、不查询补救、不补样、不充值。
未知费用保留整笔预留；同一授权只允许启动一次，不能换目录重置预算。停止后只报告已得证据和未完成样本。
