## Owner 定下的文案规则

实施时所有界面文案都要遵守：

1. 不写"每次运行前预计消耗多少积分"。
2. 演示多模型时写"模型 A / B / C"，不写真实模型品牌。
3. 不写后端没有的功能，也不写后端没有的同意开关。用户数据只能由用户自己导出后发给我们。
4. 常见问题第一条（"它和 ChatGPT 这类 AI 有什么区别？"）保留 ChatGPT 和 Claude 的品牌名。

## 仍待定的事项

以下内容在设计稿里是占位或还没有依据，实施时不能当作已定：

- 创始人寄语：页面标着"寄语待定"。
- 注册赠送 500 积分和积分包三档是"先定"：开发完、实测积分消耗后 Owner 可能调整。
- 常见问题里的积分用量："[实测后补]"。
- 工作室版的正式价格。
- 创始会员展示墙：必须先有"愿意公开"的选项，用户勾选后才能展示。
- Bright Data 和 Post for Me：实测和条款核对通过之前，相关说法（例如 Facebook 等平台的公开数据、
  海外 9 个平台的一键发布和自有作品数据）不能上线。
- "资深社媒专家编写的方法论 / 一线案例"这类说法，上线前要有依据。
- 报告预览的步骤和章节取自定位 Skill 2.6.0，这个版本还没有发布到 staging。
- 常见问题里"数据在传输和存储时都经过加密"的依据是 Supabase 公开的安全说明，没有自己核实过。
