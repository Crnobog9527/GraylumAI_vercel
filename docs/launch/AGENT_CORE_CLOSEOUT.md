## 先说结论（给 Owner 的大白话）

AGENT-CORE 是「新交互」本身：Agent 带着走流程、提问卡、右侧整理、每步确认、写报告。它挡着 RUNTIME-PROD，也就挡着上线。

**做完并验收了的**

- 可行性实测（AC-0）、提问卡和流式回复（AC-1 大部分）、定位流程里的右侧整理面板和每步确认按钮、模型写完整报告（一次完整生成已通过）。

**做了一半的**

- 右侧整理的质量：现在 77/100，V3 目标 90/100 正在做（#768）。
- 报告：能生成，但刷新、停止、旧标签页去重等情况还没验收；**写完以后不能「定稿」**，也接不上第一周选题。
- 3 秒出第一个字：服务器部分约 3.4 秒，还没从美国位置实测过，目前不达标。

**还没做的**

- Agent 读 Skill 参考文件的工具（AC1-5）。
- 定位会话的查询工具（第 31 项）。
- 其他 Skill 和自由对话用同一个工作区（AC-4）。
- 数据基础补缺和「数据使用同意」（AC-5，D5），一行代码都没有。

**需要 Owner 决定的：3 件**（第 5 节，各附推荐和可以直接复制的话）

1. 补确认：右侧整理采用「同一次执行里串行整理」（连续快速发消息时要等几秒）。推荐同意，现在实际就是这样跑的。
2. AC-5 拆分：上线前只做「同意开关 + 团队读取时只放行已同意的记录」，去身份信息和管理员案例视图随上线后的 LEARN-1 一起做。推荐同意。
3. 剩余验收的真实模型测试预算：推荐总共不超过 5 美元。

**还有什么风险**

- 剩下的活大部分是 high，有 3–4 个数据库迁移，而且和在途的 #764、#766、#768 改同一批文件，必须排队，不能并行。
- 3 秒首字可能需要换线路或换模型才能达标。
