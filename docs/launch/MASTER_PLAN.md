## 0. 一页总览

**产品主线**：业务正式定位 → Agent 按周带用户做选题 → 明确采用并保存简报 → 选中具体内容展开 → 视频口播稿定稿后询问，明确同意再生成配套分镜/剪辑建议 → 用户制作发布 → 后续自动数据回流与复盘 → 调整下一轮。

**用户主要使用两个区域**：Agent 工作区负责讨论和执行，资料库负责查看、查找、编辑和继续工作。技能广场、个人中心及必要设置继续存在，不把“两个主要区域”误读成全站只能有两页。

**实现基座**：官方 Agent SDK + 已有 Runtime/BILL2 + 私有 Skill/revision + 归属明确的业务记录。新增的是必要的工具和展示适配，不是第二套 Agent、钱包、通用记忆或流程编排平台。

**建议施工次序**：先完成 #422 的 Agent/资料库核心体验与定位入口；再完成单条内容交付及相应验证；核心稳定后推进统一输入框与管理能力，并在共享接口稳定时并行处理支付适配；连接器、社媒与多模型扩展按真实依赖分支推进；最后清理被替代的旧路径并完成整体验收。C1 已确认采用套餐式自动追踪；实际服务开放仍需确定适用套餐参数并完成供应商、技术及授权条件。

**不重复建设**：#419 的账务基础和 #421 的持久 SDK Session 已合并，应复用；它们的隔离验证不证明真实供应商、生产或新 UX 已通过。

**不让 Owner 记顺序**：任务目标、硬依赖、建议优先级、共享写入面及继续条件写在第 11–12 节。Codex 在 Owner 实际授权的具名批次内自主排序和修复；超出批次、实质产品冲突及受保护外部操作仍按 AGENTS 处理。

### 2.2 C1：套餐式自动追踪（2026-09-21 Owner 已确认）

**产品口径已确定，不再是未决阻塞。** Owner 本轮明确确认：

> 数据自动追踪对用户表现为套餐服务，默认频率由后台安排；后台保留集成用量计量，用于限额、成本和扩容，但不要求普通用户自己设置追踪预算。专业模式、加购方式和最终套餐档位以后再决定。

本决定替代 #431 中与之冲突的“普通用户自行设定频率、月预算，并默认管理前台集成额度”的产品假设，不取消其安全工程要求：

- 普通用户连接账号、理解并同意追踪范围；后台在已说明的套餐服务范围内安排默认频率。套餐式体验不代表无需用户授权，也不代表允许无限范围或无限成本。
- 后台继续记录实际请求、可用结果、内部集成用量、套餐限额、供应商成本和容量；执行准入、原子预留、冻结规则、限流、恢复与退款来源保护保留。内部预算不能变成要求普通用户手填预算的流程。
- 额度或容量不足停止新增外部采集并如实显示状态，允许历史仍可查看；不自动购买、透支或静默升级，不重复收取内部重试/恢复的费用。
- 专业模式、加购方式、最终套餐档位/价格/账号数/频率及结转规则仍待以后决定，不能沿用示例或旧提案作为售卖承诺。此前 PRO 单账号/24 小时、30 天观察期等仅保留为历史讨论，不是本次确定的套餐参数。

因此，套餐默认体验与后台计量可按这一确定方向准备；实际收费或服务开放仍需适用套餐参数、供应商能力、技术验证与相应批准。只阻塞缺少这些条件的部分，不重新阻塞无关的核心 Agent、定位与资料库工作。

其他待核验事项是技术或外部能力问题，不交给 Owner 选字段/接口：供应商实际字段与权限、批量/历史/限流作用域、SDK 固定版本能力、远端配置、真实成本协议，由相应任务调查；仅涉及业务结果、费用或授权的决定再提问。

## 3. Agent 与辅助组件的关系

### 3.1 主次

Agent 在官方 SDK 中理解意图、选取允许的 Skill、发起必要提问、调用业务工具，并根据真实结果继续指导。Skill 提供专业方法；工具处理可靠读写、权限、版本和费用；页面把进度、提问和资料清楚显示。不能在前端另写一套决定业务顺序的教练。

SDK 的工具审批、等待回答、Session 和 UI 提问卡不是同一个概念。按实际锁定版本验证可复用能力，只为缺少的产品语义作最小适配；不因截图或依赖声明推定存在开箱即用的提问工具，不默认换框架。

### 3.2 自动、提问与直接操作

| 类型 | 行为 |
| --- | --- |
| 自动 | 保存聊天与草稿、加载当前已授权资料、整理有依据的暂定信息；不把猜测写成已确认事实 |
| 必要提问 | 只询问真正缺少的信息、用户偏好或授权；先给推荐，再给少量结构化选项，允许自然语言、自定义、稍后或帮我决定 |
| 明确采用 | 自然语言“保存这三个”和选择含义明确的采用选项，执行同一个业务动作；不用再点第二次确认 |
| 直接操作 | 资料查看、编辑、历史、连接授权等仍有适当入口；其真实结果同步给 Agent，不要求用户把点击行为复述一遍 |

“选一个讨论方向”不等于“采用这组正式内容”。含糊同意、帮助请求、不知道、关闭卡片、打开链接都不能变成生成/采用授权。用户的“帮我决定”只覆盖当前明确范围，不推导长期扣费、账号发布或其他权限。

### 3.3 操作与会话一致

保存结果、目标账号、具体对象与版本、保留的草稿及失败状态形成可恢复的业务事实；对话提示和 Agent 上下文读取同一事实。自然语言与卡片不能各造一条保存/计费链。保存成功后模型回应失败，保留已保存状态，只恢复应恢复的后续工作。

同一确认的双击、双标签、语言加点击、旧卡片及丢回包必须检查原意图与版本，避免重复成果、承接或自动后续执行。普通保存/确认本身不收费；需要模型理解或后续生成时按已授权任务与冻结预算处理，不偷加未经说明的调用。

### 3.4 主动教练而非强制关卡

默认按周制定计划，数量适应用户目标和制作能力，不固定七条。已有本周选题尚未验证又要批量生成时，建议先执行并寻找有效模板；用户坚持则尊重，不锁住、不反复劝阻。没有证据时不声称找到了稳定模板。

用户明确切换业务/工作时保留当前进度并切换已授权上下文；一句延伸问题不自动建立新任务。右侧摘要容器保持稳定，切 Skill 不清空成果；迟到输出仍归原工作，不随当前页面改变归属。

## 4. 定位准入与业务归属

### 4.1 两条入口，一个完成标准

没有正式定位版本的用户，每次登录进入首页显示“我是新手 / 我已有定位”两种选择，并提示正式策略完成前不能开始选题等后续创作；已有草稿继续恢复，不重复创建。完成正式定位后不再显示新手弹窗。

- 新手：由定位 Skill 按其方法、步骤与停止条件进行完整引导。
- 已有定位：进入资料库，按同一标准填写完整有效的策略资料，可以跳过引导 Skill，但不能跳过策略本身。
- 信息不足：可带已填内容进入定位 Skill，由 Agent 补齐和核对，不清空、机械重填或自动确认已有内容。
- 正式版本创建前，允许资料查看/编辑和定位讨论；限制后续创作，不封死完成定位所需入口。

### 4.2 信息完整与深度不同

缺少必需信息、空泛到实际没有回答问题的内容必须补齐。真实、相关且完整但较粗浅时，Agent 解释局限并推荐深入；用户理解后明确采用，可以创建正式版本，不设不可见主观质量分数无限阻拦。模型不能凭“想了解更多”延长流程。

延期/不知道作为进度与局限保留，不冒充已确认事实或绕过必需信息的有效性。步骤与字段要求来自固定 Skill 配置，不把六个阶段或业务问题写死成全平台 schema。

### 4.3 业务、平台和账号

一份核心定位属于一项业务/品牌；同一业务多平台账号共享核心定位，并有各自账号阶段、受众/表达和平台策略；不同业务有独立正式定位。已完成一个业务的用户不再被全局当新手，但新业务仍需满足自己的前置条件。

这是产品关系，不要求重建现有项目表或复制账务/Session。执行者先核验现有所有权、定位引用和账号项目，作兼容扩展；旧项目身份、历史来源和费用不搬家。核心定位修订不静默改写已经采纳的账号策略或历史成果，按实际影响提示复核。

### 4.4 保留原 #422 未全部关闭的要求

导师主动发起当前问题；层级题号与当前字段一致；只展示已到达和当前问题、不暴露未来题量；顺序稳定；区分已确认、待定/延期和进行中；延期可回看编辑后明确确认；只保留一个动态标题。未知/求助/简单应答不直接成为策略答案。

导师先呈现事实、假设、依据和建议；独立信息提取模型须有真实角色/配置/消费接线，不能把导师输出补丁改名当成完成。保留完整公开对话、手动编辑优先与跨轮次隔离。6.4 卡顿等历史体验按实际复现与阶段耗时判断，不通过移除安全检查“修复”。模拟回复不能证明真实模型质量或真实延迟。

## 5. 周选题、资料库与内容交付

### 5.1 从正式定位到选题

确认正式定位先保存，再询问是否开始第一周选题。“稍后”、关闭或仅打开链接不启动生成。用户明确同意后，Agent 读取准确的正式定位/方法版本及独立工作 Session，启动一次可恢复的首轮；信息充分就提出方案，缺关键信息才问，不让用户机械重复“请生成”。

讨论和修改自动保存草稿；明确采用全部或部分内容时，保存实际对应的可追溯版本与账号集合，再复用原子承接。界面不要求用户理解“候选保存→子集版本→采纳→承接”四个独立手续，但服务端安全检查不能删掉。

聊天、保存、采用都恢复完整原冻结负载，不只留 UUID。原 planId、来源版本、body、账号集合、首次 expectedRevision 和原 input 均保持；账号新 revision 不能改变未知请求的重放内容。确定拒绝后才允许核对并发状态、明确建立适当的新请求。

### 5.2 资料库

默认按业务和平台/账号组织，支持时间范围查找，展示账号当前阶段及历史时点；阶段未知就如实显示，不按使用天数编造。周是范围/记录，不是每周一套新页面。卡片/列表默认展示易读摘要，详细简报按需展开，不把所有字段铺成横向大表格。

正式成果优先可见，草稿可恢复但明确未确认；进入某选题时带准确资料和原讨论，不落到无归属空聊天。修改后 Agent 能读取实际新值，历史建议不得撤销用户已保存的清空操作。原有定位、选题、长文、版本和恢复入口保留，不新增平行内容库或 RAG/网盘。

### 5.3 交付深度与视频链路

每个正式选题保留完整简报：讲什么/给谁看、为什么与定位及当前目标相关、主要表达结构、要验证的假设。日期、平台、账号和来源能追溯，标题不替代完整简报。

确认选题不自动生成所有文章或视频脚本。用户选定具体内容继续工作后，使用对应 Skill 讨论和修改稿件。**视频口播稿明确定稿只表示口播稿完成，不授权派生生成。** Agent 主动询问是否基于这版继续；用户可选择分镜与剪辑建议都生成、只生成分镜、只生成剪辑建议或暂时结束。只有明确同意才执行，自然语言与提问卡执行同一个业务动作，不重复确认。此为 Owner 对 B1 / CONTENT 的已确认修正。

分镜对应口播段落、画面/演示/补充素材及建议时长；剪辑说明开头、节奏、画面切换、字幕强调及声音处理。结合用户设备、时间和能力，给新手可执行方案。它们与简报、口播稿属于同一选题；修改口播稿后标明配套版本是否仍匹配，重新定稿时把旧分镜/剪辑标为旧版本或不再当前匹配；不自动重新生成，必须再次取得明确同意。

不扩展为自动图片/视频生成、实际剪辑执行或媒体托管；后续对外发布工具也不能由“确认稿件”隐式授权。

## 6. Skill、上下文、模型与编辑器

### 6.1 Skill 基座

保留私有标准目录/完整入口/按需资源读取，不展平整包后冒充目录运行；普通用户只看允许元数据和自己的成果。发布原子、失败保留旧版；轮次固定 revision、包/工作流/模板身份；升级明确复核受影响内容，不改旧确认和报告。

保持三步/六步/八步及额外配置样本、非工作流 Skill 的同核心能力。配置包含稳定 ID、顺序、依赖、信息/成果结构、必要资源/能力和停止条件，不允许任意可执行脚本。非法依赖/资源/未支持能力在外部调用与扣费前拒绝；没有研究需求不强制搜索。确认失效沿声明依赖传播，保留内容和历史，不强制无关重生成。

正式定位报告从已确认快照确定性汇编，默认不调用模型；导出忠实保留来源/局限，重复下载不创建新版本。模型生成的稿件则记录实际执行来源，不与确定性报告混淆。

### 6.2 上下文与模型职责

所有相关入口在服务端解析授权用户、业务、账号和当前工作。已确认经营资料和已保存成果是事实来源，摘要只补充；长历史/其他成果受控按需读取，不要求用户复制，也不默认把全部 Session 合并。新工作取当前适用版本，原请求恢复保留原快照并遵守当前权限/撤回限制。

普通模型由用户在允许目录选择；Skill 模型、独立整理/提取角色、智囊团参与/综合模型由管理员配置；普通选择不覆盖其他角色。显式 Skill 优先，自动匹配先读公开元数据，选中后才加载私有方法。用户禁止联网时不搜索；要求最新但能力不可用时说明，不假装已经研究。

### 6.3 统一输入框（吸收 #424）

沿用 `V3-OPC-UI`，不新建编辑器 Launch 身份。核心纵向链路完成后实施；此前输入法误发送或草稿丢失等真实 blocker 仍由核心任务最小修复。

### 6.4 发现与展示

保留顶部一级技能广场、共同 catalog、模型角色和权限；连接器仍位于输入框菜单/抽屉/设置子页，不升为一级导航。资料库作为主要查找入口，旧“项目”入口在受控切换后指向它，不额外复制第二份项目资料。

## 8. 连接器、发布、数据同步与复盘

### 8.1 共享原则及飞书

飞书/Notion/Slack 与 Post for Me 并存，不是二选一。兼容 MCP 优先使用标准客户端和实际能力，协议/认证/业务不兼容处才适配。现有 AgentKey 客户端是特定契约，不等于任意 OAuth 服务改 URL 即用；HTTP/OAuth 与本地进程服务按实际托管方式分别验证。

模型只看到当前所需的允许工具；外部内容不能升级成系统指令；用户/连接/目标对象必须由服务端校验。跨用户 ID、撤权、无效 schema、扩权、结果超限明确拒绝。

`V3-FEISHU` 保留 OAuth→选择 Base/表→读字段→映射→写入预览→创建→同记录幂等更新。外部写须明确目标、内容或有效自动同步授权；未知结果先核对。Notion/Slack 为后续相同边界适配，不为所有服务建一个新 Agent。

### 8.2 社媒发布与采集

Post for Me 是 #431 的选型输入，实际商户合同、平台权限、字段与托管能力仍需验证。其本地 code-mode MCP 说明不是多租户远程 OAuth 已完成的证据。定时任务优先调用受控固定服务端 API/SDK，Agent 工具也走同一业务入口，不能把全项目 API key 或任意 SDK 执行权交给用户模型。

账号连接、指标读取、发布及自动跟踪同意分别表达；已连接不代表已授权发布。发布冻结内容、目标账号、时间和确认身份；未知结果先核对原发布，不自动换账号/供应商重发。新作品发现与已知作品更新分开；按支持能力增量/批量取数，使用适用 Webhook 并验签去重，不假设平台推送全部指标变化。

### 8.3 有界追踪与前台体验

保留两份来源共有的方案：账号概况与新内容重点观察；历史资料可查不等于全部内容永久每日刷新；观察期/复访量有界，优先批量和增量；已有缓存展示及 Agent 读取已有快照不重新采购数据。

自动采集不依赖用户在线；登录/页面只检查新鲜度，不全量抓取；当前复盘可优先更新必要范围，但仍受授权/额度约束。新旧时间范围、统计期和实际采样时间分开。首次导入有范围/分页上限、预估和可恢复进度，部分完成透明，不无预算扫描全部历史。

按 C1 提供套餐式自动追踪，由后台安排默认频率；普通用户不必管理追踪预算。内部集成用量用于限额、成本和扩容。此前 PRO 每日一账号和 #431 的用户调频率/前台双用量仅作历史来源；专业模式、加购方式和最终套餐档位以后决定，不转为当前售卖规则。

### 8.4 调度与配额

这是受限的产品同步任务，不是 Codex 开发任务调度器，也不扩成通用自动化平台。复用可用的现有存储/限流/任务记录，补具体缺失能力；已有 scheduledJobRuns 记录不等于持久队列。

| 约束 | 必须行为 |
| --- | --- |
| 共享出站限流 | 所有页面、Agent、定时、导入和适用发布共用供应商真实作用域的秒/分钟限制；并发数与速率分开；作用域未知时保守共用，不用多个 key 绕过 |
| 公平与优先级 | 当前发布/授权、当前复盘、周期采样、历史导入分级；按用户/账号轮转并防饿死；稳定错峰；积压可见，不承诺拥塞仍准点 |
| 持久恢复 | 持久任务、分页游标、占用和原请求身份；重复/重启不丢进度、不重扣；同一游标链顺序推进；兼容范围复用结果但不跨租户混用私有指标 |
| 错误 | 限流不可用排队而非放开；429 按实际 Retry-After 有界重试并重新过限流；未知写操作不套用普通读取重试 |
| 权益与成本 | 若采用集成额度，复用公共订单/履约及来源保护，不建第二现金钱包；任务范围与规则冻结，原子预留、按明示交付单位结算；不偷偷改变未交付故障退款规则 |

#431 观察的 5 次/秒、40 次/分钟及建议 4/36/28 内部阈值，只是待复核采购资料，不是代码常量或 SLA。固定供应商月费、单次官方成本、估计和内部分摊分列；自动同步不能伪造聊天 Session/选题挂账，账号/周期任务作用域需要兼容扩展并验证。

额度不足停止新外部任务、保留允许历史；不会自动购买。退款/撤销后迟到释放不能复活已退权益。管理员改规则不重写已发请求；周期、结转、补充包与价格待确认。

### 8.5 复盘的证据标准

平台指标字段以实际权限/供应商可取能力为准，由平台 Skill 提出需求和解释，统一服务执行。用户不被要求手填基础运营数据；自动取不到就标缺失与局限。播放/互动等是新手直观反馈，评价仍结合定位目标；没有咨询/注册/购买证据时不能宣称获客已验证，也不强制接独立站成交归因。

保存指标语义/单位/分母、平台账号作品、来源、统计截止期、采样时间与完整性。累计值不能反造接入前每日曲线，两次采样差不自动等于自然日增量；缺测非零、旧数据非刚更新、部分平台成功非全成功。对原因给可检验假设，不用相关性冒充因果。

数据更新不等于每次启动模型分析；在有意义节点/变化按授权预算复盘。对标账号研究保留同源/权限/成本接口边界，暂不实施，不许无限监控或规避平台限制。

## 9. 唯一账务与 Waffo MoR

### 9.1 保留 BILL2 与旧钱路的核心约束

恢复使用真实已知 provider ID 及验证过的查询能力；自造 UUID 不等于供应商可查询键。已结算或已退款终态不能被迟到回执翻转。订阅退款、quarantine、reversed 与 termination 的原来源保护继续覆盖在途 AI/集成预留。

### 13.3 证据层次及生产边界

隔离 synthetic 验证行为、状态、权限、并发、账务恢复；真实 SDK/供应商协议及模型输出质量需要各自证据。真实模型/取数/支付或远端验证在完成可审阅准备、明确目标和有界预算后按当前批准执行；未获准项目标 NOT_RUN/BLOCKED，不因此伪造通过，也不阻止独立本地工作。

M3 固定代码/schema/Skill包/能力配置身份，完成全部适用矩阵，无可复现阻塞问题。保留条款、支持收件/SOP、税务/商户条件、MFA、SMTP投递、备份/PITR、供应商容量/余额及生产安全等原发布要求；历史已勾选不是当前验收。

发布顺序仍须证明 schema 与旧 runtime 向后兼容、远端准备在新代码接管前完成、生产候选身份正确、CAPTCHA前后端配对、实际 cron 和有界真实支付/退款/模型冒烟及同日对账通过。不能假设 maintenance 会挡 cron/webhook，不能假设现网无用户；环境和真实影响需当次核验。保持 forward-only/兼容回退、停新请求和证据保留，不能恢复公开敏感 RPC 或重置余额。

本计划不执行上述外部动作、不提供生产批准；原 G0–G8 的实质验收映射到本节，废弃的 Gate/报表流程不恢复。
