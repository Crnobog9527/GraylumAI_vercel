## 验收口径（调用前冻结）

- 约 100 个整理输入，每题明确目标 stepId/fieldId、必须保留的事实、禁止内容。
- 覆盖字段分界、前轮限定、受保护字段建议、建议撤回、跨步骤信息和元指令隔离。
- 当前 Skill 包、标准答案、当前 staging 代码、实际请求及导师回复分别冻结哈希。
- 导师按现有 Sonnet 5.5 配置仅生成一次；Luna openai 线路复用相同输入跑三遍。
  整理输出上限 2048、输入预算 64000；保持现有请求的思考设置，不新增 reasoning 参数。
- 主指标：一题的全部必需事实落在正确字段，禁止内容不出现，建议状态正确才算通过。
  同时报告逐项命中率；不以较宽松的命中率替代整题正确率。
- 同一输入的三遍结果匿名混排，独立评分锁定后再揭示运行编号。
  公布每遍分数、均值、范围、标准差与逐题一致性，不把三遍当成独立的 300 个场景。
- 目标正确率至少 90%，受保护字段直接改动为 0，格式错误不超过 1%。
  宿主不支持的目标操作仍纳入失败，单列归因，不从分母删除。

## 第一遍分类与归因

| 类别（每类 10 题） | 正确 |
| --- | ---: |
| 目标与变现边界 | 9/10 |
| 赛道与产品边界 | 10/10 |
| 受众边界 | 9/10 |
| 已有条件与投入资源 | 10/10 |
| 前轮限定保留 | 10/10 |
| 受保护字段新建议 | 10/10 |
| 受保护建议累计合并 | 0/10 |
| 过期建议明确撤回 | 0/10 |
| 跨步骤信息与采纳决定 | 5/10 |
| 请求与元指令隔离 | 10/10 |

27 个失败中，建议合并 10 个、撤回 10 个、其他字段/跨步骤/限定问题 7 个。
多标签失败统计为字段误归 5、漏写 9、旧建议覆盖 7、限定丢失 8、建议未撤回 10、请求入值 1；
同题可有多个标签，因此不能把标签数量相加当成失败题数。

- **宿主/协议明确缺口：**10 个撤回题没有可用撤回操作，现有协议只能写入建议，不能删除旧建议。
  7 个建议合并题直接出现旧建议内容被覆盖。源码确认整理输入不含待采纳建议，写回对建议整值替换；
  这两点不能仅靠换模型修复。另 3 个建议合并题主要表现为未更新目标建议或信息进入别的字段，
  兼有字段分界/提示词因素，不把全部 10 个合并失败都武断归为同一个直接原因。
- **字段及提示词问题：**其余 7 个失败包括信息漏入目标字段、额外事实进入错误字段、
  已采纳的跨步骤方案未落到目标字段及排他限定被放宽。
  当前 `agent_proposal` 规则只接受导师明确推荐，与用户明确采纳/自述方案存在张力；
  本阶段没有做字段说明或提示词的对照修改，不能凭一次输出区分各因素的因果贡献。
- **评分边界：**标准答案在调用前固定，逐项字面检查加独立语义复核；额外错字段写入即使要点全中仍算失败。
  100 题为定向压力集，20 题刻意覆盖现有宿主缺口，不能把 73% 与旧 30 题的 25/30 当成质量回退。
  旧评测使用不同字段结构；本轮没有与其他模型对照，不能推断模型能力上限。
- **场景边界：**为进入后续步骤，本机夹具设置前置步骤有效；这是固定状态下的写回诊断，
  不是完整三轮对话或浏览器端到端验收。

结论：当前已完成的一遍足以暴露建议状态处理和跨步骤字段捕获问题，但不足以给出三遍基线波动。
保持既定 Luna 和思考设置；按原阶段顺序推进的前提，是主窗口先审计本次中断与不完整基线。
不跳过阶段审计，也不提前实施字段、提示词或建议协议修改。
