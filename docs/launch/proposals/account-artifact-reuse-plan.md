## 1. 唯一推荐：从明确报告发起一份独立脚本

已有用户本人可访问的正式定位报告 → 点击“基于此定位创作脚本” → 服务器带入已校验账号归属、固定该来源版本并创建独立作品 → 在现有聊天完成脚本 → 确认、保存 → 从现有成果列表找回。

首批不先建账号中心。复用现有聊天、成果列表、项目/轮次、确认快照和报告阅读组件；列表只补闭环需要的作品标题、关联账号、来源版本与返回入口。长报告进入现有宽屏/手机阅读视图，不在侧栏堆全文，不建立第二套报告存储。

| 范围 | 定义 |
| --- | --- |
| 首批验证样本 | 一份六步定位正式报告，同账号、同一个已配置 YouTube 脚本 Skill，独立脚本 A/B 与 A 的修订 |
| 产品能力边界 | 经服务端校验的一份定位→脚本引用配置，支持同账号同 Skill 多份独立作品；不是任意跨 Skill 调度，也不代表其他模块已接线 |
| 首发必需项 | 仍以现有 Master Plan/V3/REL-1 为准；本提案不新增首发门槛，不自动选择任务或声明 ready |

没有可用定位时，仅此“基于定位创作”入口不可开始，提示选择用户本人可访问的正式定位或返回定位流程；读取失败与确实缺失分开提示。普通聊天、已有脚本入口和纯提示词模块维持原规则，不把定位变为全站新增前提，也不新增未经确认的“无定位模式”。

不做账号管理平台、知识库、向量检索、模型总结定位、OAuth、团队共享、任意导入、SDK 迁移、自动选资料或多 Skill 自主执行。站内发布正式版本不等于向社交平台发布。

## 3. 新作品、修订与账号身份

- **新作品**：用户明确发起一次创作，获得新的 project/work ID；同账号同 Skill 的 A、B 是不同项目，可同时有草稿，各自确认、发布、找回。
- **同一作品的新版本**：在指定作品内新建修订 round，沿用该 project/work ID；已有正式版本不可覆盖。A v2 不修改 B 的草稿、正式版本、来源或对话。
- **打开/恢复**：显式 project/round 身份，继续原作品原请求；不能按 `projects[0]` 或最新时间选择。列表打开不得创建版本或模型调用。
- 同一次创建的网络重试复用稳定幂等键，只得到 A；用户另点“新建脚本”使用新的操作身份得到 B。不同作品允许并行草稿，单作品既有 active draft 约束保留。

未来最小实现必须同时调整项目创建语义与数据库唯一约束：明确区分原定位项目和独立脚本作品，只为经配置的脚本用途允许多项目；原定位账号唯一项目约束继续生效，其他旧项目语义保持。不能整体删除账号唯一保护，也不能伪造账号、Skill 或 module 来绕过。旧项目按既有用途兼容识别，历史不移动、不合并；未来迁移需验证原数据、并发创建、幂等、约束与回退，不在本文预占编号或改写 0066。

账号关联由已鉴权源定位项目派生，沿用原授权范围并存最小稳定关联；不要求先建立通用账号实体/管理界面。客户端只提供源与动作身份，服务器验证源所属、目标 Skill 准入及关联。相同显示名、空账号或历史歧义不自动绑定；来源不能确定时阻止此引用入口，原成果仍按既有权限找回。

## 4. 固定版本引用与项目内证据的衔接

引用配置只有一份经审阅、经 schema 校验的定位→脚本配置，声明允许的源/目标类型、稳定章节 ID、必需内容、容量和配置版本；不是自由代码。私有方法仍由原加载器授权读取。

目标轮次持久化引用身份：源 project/round/report、正式版本、确认/章节 ID 和内容 hash，目标 project/round、账号关联及配置版本。从明确报告启动就固定该版本；源随后发布 v2 不切换在途 v1。用户主动采用 v2 时另开该作品修订，不自动生成或覆盖。

为连接现有项目内证据检查，拟增加最小的**目标项目所属引用记录**：目标证据 ID 与源 evidence/provenance ID 分开存放，源 ID 带源项目/版本身份，仅由服务端解析器读取。目标本地证据检查验证目标归属，再经引用解析器验证源身份、快照及完整依赖可用性；目标步骤的 evidenceIds/provenanceIds 只包含合法目标记录。不得把源 ID 冒充目标 ID，也不得把复制的正文登记成无来源限制的普通证据。

解析取得源不可变快照，不另建正文库；将必要章节及引用身份一次性加入上下文，保留原依赖限制。源解析、版本固定和目标准入需一致，不能混用 v1/v2；后续采用/查看仍检查当前权限，快照固定不代表永久授权。

## 5. 内容权限与已派发请求收尾分开

这里引用的是**用户本人可访问的正式成果**，不是公开或跨用户共享成果。查看历史成果的权限与执行目标 Skill/方法版本的许可分开。源资料按不可信输入处理，不覆盖系统/私有方法；私有指令、凭证、manifest、执行令牌与原始推理不进入用户成果。

| 动作 | 来源撤销、删除、过期或权限不足时 |
| --- | --- |
| 新生成、采用/确认、发布、预览/查看、导出 | 校验源/目标归属和引用依赖；禁止不可用来源及依赖它的内容使用。读取失败保留未知，不冒充有效或不存在 |
| 已派发且存在可信已知结果的费用收尾 | 依原请求身份、可信结果与既有消费规则幂等收尾；不因源不可读而重生成、免单、盲退款或跳过应结费用。收尾成功不授予正文查看/采用权 |
| 执行/费用未知 | 保留 unknown，沿用原恢复规则核对；不以撤销来源猜测供应商是否执行，不重新派发 |

**首批处理粒度为引用绑定的目标成果/版本及其依赖后继**。任一必需源依赖不可用时，保守阻止该目标成果正文的查看、采用与导出，必要时整份组合报告不可用；保留允许展示的非敏感状态/身份提示。引用派生的聊天回答也遵循该限制，不能通过原对话绕过。无依赖的独立作品不受牵连。沿用原删除要求，不以财务收尾需要为由复制或永久保留受限正文。

不承诺逐句溯源、自动删净受限语句或部分可安全导出。已在撤销前合法下载到用户设备的内容无法由网站追回；服务端后续读取/使用必须阻止。实施需验证既有状态/receipt 响应不会在收尾时附带泄露被限制正文。

## 6. 最小上下文和成本

按配置确定性提取必要定位章节，输入安全检查后与本次指令、目标作品获准历史组装一次。完整历史可见不等于模型可读取其他作品；固定来源不替代实时授权。最终容量包含模板、来源、历史和输出预留；超限在预扣/派发前拒绝或请用户缩小范围，不静默丢定位、换模型或增加总结调用。

复用原生成与原子消费链路。既有 reply/summary 调用需分别计数，不能承诺一次创作只有一个供应商请求；新增引用解析不新增模型调用。列表、打开报告与找回不生成。账务在后台处理，不要求用户确认费用。不估报未经测量的速度、美元成本或工期。

## 7. 路径比较与最小施工范围

| 路径 | 结论 |
| --- | --- |
| 先建通用账号中心，再提供任意跨 Skill 选择 | 多出账号管理、发现和调度范围，不采用 |
| 知识库/检索/SDK 迁移或手工复制正文 | 前者增加系统和成本；后者丢失稳定来源限制，均不采用 |
| 明确正式报告直接发起独立脚本 | 推荐；只补作品身份/约束、最小账号关联、一份引用配置及现有证据适配，复用聊天/成果/阅读 |

后续只建议一个有界实施范围：**报告发起→独立脚本 A/B→确认保存找回**。内部顺序是作品身份与旧约束兼容 → 固定版本/来源权限适配 → 现有入口与组件接线 → 隔离端到端验证。不是新增平台或多个治理阶段。涉及 SQL/权限的后续实现须按 high 验证，本轮文档修订为 ordinary。

## 8. 必须取得的验收证据（最终状态见交付记录）

- 同账号同脚本 Skill 创建 A/B，两者可并行草稿、独立确认保存及找回；A v2 不影响 B，重试创建 A 不产生第三份；原定位唯一约束、旧空账号项目、原 social 冲突保护兼容。
- 报告固定 v1，源并发发布 v2、刷新、双标签、迟到响应仍不混版本；主动修订才采用新版。打开、恢复不新建作品/轮次。
- 源 evidence ID 注入目标、伪造 source/target、跨用户、同名账号、失效映射全部拒绝；目标引用 ID 和源依赖可验证且不可经复制正文绕过。
- 源撤销发生在准入前、派发后、可信结果已记录后、结算后：分别检查内容查看/采用/导出、原对话和报告通路，以及原请求幂等结算；已知结果正常收尾、unknown 保留、不重生成/预扣/重复结算/盲退款。
- 可计数供应商替身核对实际消息与来源只组装一次、作品上下文隔离、必要过滤和容量检查；保留现有 reply/summary 计费与私有 Skill 允许/拒绝矩阵。
- 长报告阅读、手机、返回聊天位置、缺失与读失败、独立作品找回；没有定位只限制本引用入口。普通聊天、纯提示词、无步骤和多步骤原流程不退化。

使用现有隔离 SQL/Auth/HTTP/浏览器与计数替身，不调用真实模型制造异常。需实测过滤/应用开销才可报告性能；真实 provider 验收另需明确授权，不沿用历史预算。
